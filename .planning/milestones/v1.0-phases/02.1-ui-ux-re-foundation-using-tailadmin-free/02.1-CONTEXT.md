# Phase 2B (02.1): UI/UX Re-foundation Using TailAdmin Free - Context

**Gathered:** 2026-10-08  
**Status:** Ready for user review  

<domain>
## Phase Boundary

Completely rework the clinic management application's visual system, layout, component architecture, responsiveness, and overall UX foundation using the **TailAdmin Free Next.js Admin Dashboard** as the visual and implementation reference.

This is strictly a **design-system and UI/UX refactoring phase**, not a feature-development phase. All existing Phase 1 and Phase 2 business logic, Supabase database schemas, permissions, audit logging, consent tracking, deduplication algorithms, and scheduling workflows are preserved without functional regression.

The target outcome is a cohesive, calm, professional healthcare SaaS application that feels like a polished commercial product rather than an AI-generated prototype or a generic template.
</domain>

<decisions>
## Implementation Decisions

### D-01: Git Branch Isolation
- **Branch:** `phase-2b-tailadmin-ui` (will be branched directly from current HEAD upon user approval).
- **Isolation:** Main branch remains untouched. If the TailAdmin direction is discarded, the branch can be abandoned cleanly without leaving residues in the core repository.

### D-02: Architecture & Domain Boundary Preservation
- **Source of Truth:** The existing application architecture (`app/`, `components/`, `features/`, `lib/`, `supabase/`, `tests/`) remains the authoritative architecture.
- **Role of TailAdmin:** TailAdmin is a visual and component reference only. No TailAdmin domain code or full project structure is copied. Presentation remains strictly decoupled from domain logic and data fetching.
- **Design System Isolation:** Generic visual primitives live in `components/ui/` and `components/layout/`. Feature-specific components (`components/patients/`, `components/calendar/`, `components/queue/`) consume these primitives.

### D-03: Design System Reconciliation with DESIGN.md
- **Light Theme Only:** Strict enforcement of `DESIGN.md` §2.1. Dark mode tokens, dark theme contexts, and dark shells from TailAdmin are stripped/bypassed.
- **Brand Palette:** The canonical healthcare blue `#1769E0` (`var(--brand-primary)`) is mapped to the brand token scale (replacing TailAdmin's `#465fff`).
- **Typography:** Retain **Inter** as mandated by `DESIGN.md` §6.1, structured into a clean scale (`page-title`, `section-title`, `card-title`, `body`, `label`, `caption`, `tabular-nums`).
- **Surfaces & Borders:** Clean white cards (`#FFFFFF`) on warm neutral canvas (`#F7F6F3` / `gray-50`), with 1px border (`#E4E5E7` / `gray-200`) and subtle shadows (`shadow-theme-xs` / `shadow-theme-sm`).
- **Touch Targets:** Maintain 44px minimum touch targets on all interactive controls for mobile usability in Tier-2/Tier-3 clinics.

### D-04: Dependencies Strategy
- **Add:** `clsx` and `tailwind-merge` (for robust conditional Tailwind utility composition).
- **Exclude / Do Not Add:** Do not add `next-intl`, `@fullcalendar`, `swiper`, `@react-jvectormap`, or `@svgr/webpack`.
- **Icons:** Use the already-installed `lucide-react` for all navigation and interface icons.
- **TypeScript Config:** Add `"docs"` to `"exclude"` in `tsconfig.json` so the reference directory `docs/temp/...` does not interfere with root project typechecking or Next.js build.

### D-05: Sidebar Application Shell
- **Desktop:** Collapsible sidebar (290px expanded, 90px collapsed) with clear active item indicators (`bg-brand-50 text-brand-600 font-semibold`), grouped navigation ("Operations" and "Management"), and tenant brand header.
- **Mobile:** Off-canvas drawer sliding from left with translucent backdrop overlay (`Backdrop.tsx`), controlled by `SidebarContext`.
- **Header:** Sticky top bar with hamburger button on mobile, sidebar toggle on desktop, clinic name with role badge, global search bar (`Cmd+K`), and user profile menu with Sign Out action.

### D-06: Domain Screen Modernization
- **Dashboard (`/`):** Summary metric cards (Queue count, Appointments scheduled, Active staff), quick front-desk actions, and active queue overview.
- **Patients (`/patients`):** Professional data table with search, status badges, registration button, and structured empty state.
- **Patient Detail (`/patients/[id]`):** Profile header with ABHA badge, demographic overview card, consent timeline, and visit history.
- **Patient Registration (`/patients/new`):** Segmented card sections (Demographics, Age/DOB dual sync, ABDM, Address) with non-blocking duplicate warning banner.
- **Doctor Calendar (`/calendar`):** Day timeline grid by doctor, slot-click booking drawer, waitlist promotion drawer, and overbook confirmation modal.
- **Live Queue (`/queue`):** Real-time reception queue with token chips, doctor filter, 1-tap status progression ("Call In", "Consulting", "Completed"), and walk-in drawer.
- **Staff & Settings (`/staff`, `/settings/*`):** Team member directory with role badges, staff invite card, clinic profile and billing management cards.
- **Auth & Onboarding (`/login`, `/verify`, `/join`, `/clinic/new`):** Clean, professional centered card layouts.

</decisions>
