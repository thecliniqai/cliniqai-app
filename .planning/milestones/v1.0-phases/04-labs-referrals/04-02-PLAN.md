<objective>
Implement zero-overhead lab recommendations, document uploads, and patient viewing for Phase 4:
1. Build the Labs data access layer in `features/labs/` supporting document uploads, filename auto-amendment (`[Patient_Name]_[Original]_[Date].ext`), private storage uploads via `lib/storage/`, and document management actions.
2. Build the tokenized patient document share mechanism generating 64-hex cryptographically random tokens with 7-day TTL and access tracking.
3. Build the public zero-login patient report viewer at `/reports/view?token=...` and its backing route handler `app/api/reports/view/route.ts`.
4. Build the dedicated "Lab Reports & Records" tab in `components/patients/patient-lab-documents.tsx` and integrate it into `components/patients/patient-detail-view.tsx` and visit history.
5. Enhance Consultation Cabin (`components/consultation/consultation-workspace.tsx`) investigation recommendations to seamlessly print on prescriptions/requisitions without catalog overhead.
6. Verify all lab document and tokenized sharing integration tests pass.
</objective>

<threat_model>
| Threat ID | STRIDE Category | Component | Description | Severity | Mitigation |
|-----------|-----------------|-----------|-------------|----------|------------|
| T-04-04 | Tampering / Malicious Upload | `uploadLabDocument` action | User uploads executable script or HTML file disguising as PDF/image leading to stored XSS. | High | Strictly validate MIME types (`application/pdf`, `image/jpeg`, `image/png`, `image/webp`) and file signatures; enforce 25MB max size; sanitize filename removing traversal characters. |
| T-04-05 | Information Disclosure | `document_share_tokens` | Attacker brute forces or guesses patient share tokens to view confidential diagnostic records. | High | Generate tokens with 256-bit cryptographic entropy (64-character random hex); enforce 7-day expiration; record access counts; provide staff revocation capability. |
| T-04-06 | Broken Object Level Auth | `getPatientDocuments` & `deleteLabDocument` | Front desk staff or attacker accessing documents across clinics. | High | Verify `getActiveMembership()` and scope queries to `session.tenantId` with PostgreSQL RLS enforcement on `patient_documents`. |
| T-04-07 | Denial of Service | File Upload Endpoint | Attacker floods storage bucket with oversized files exhausting clinic quota. | Medium | Enforce 25MB file size limit in server action and storage bucket constraint; require authenticated session for all uploads. |
</threat_model>

  <action>
    1. Create `features/labs/types.ts`:
       - Define TypeScript types: `LabDocumentItem`, `UploadLabDocumentInput`, `ShareTokenResult`.
    2. Create `features/labs/schema.ts`:
       - Define Zod schema `uploadLabDocumentSchema`:
         - `patient_id` (UUID), `visit_id` (optional UUID), `title` (string 1-255 chars), `document_type` (`lab_report` | `imaging` | `prescription_scan` | `other`), `report_date` (ISO date string), `notes` (optional string), `is_abnormal` (boolean default false).
       - Define Zod schema `generateShareTokenSchema`: `document_id` (UUID).
    3. Create `features/labs/actions.ts`:
       - `uploadLabDocument(formData: FormData)`:
         - Validates session via `getActiveMembership()`.
         - Extracts file and metadata from FormData.
         - Validates MIME type against `['application/pdf', 'image/jpeg', 'image/png', 'image/webp']` and size <= 25MB (26,214,400 bytes).
         - Resolves patient full name from `patients` table.
         - Sanitizes patient name: `patient.full_name.trim().replace(/[^a-zA-Z0-9]/g, '_')`.
         - Sanitizes original filename: `originalFile.name.replace(/[^a-zA-Z0-9.-]/g, '_')`.
         - Computes auto-amended filename: `${cleanPatientName}_${cleanOriginalName}_${reportDate}.${ext}` (per decision D-03).
         - Defines storage key: `tenants/${session.tenantId}/patients/${patient_id}/labs/${amendedFilename}`.
         - Uploads buffer using `uploadFile()` from `lib/storage/`.
         - Inserts row into `patient_documents`.
         - Records audit log: `action: 'patient_document.upload'`, `entityType: 'patient_document'`, `entityId: newDoc.id`.
       - `getPatientDocuments(patientId: string)`:
         - Queries `patient_documents` where `patient_id = patientId` and `tenant_id = session.tenantId`, ordered by `report_date DESC, created_at DESC`.
       - `getDocumentSignedUrl(documentId: string)`:
         - Verifies tenant access; calls `getSignedUrl({ path: doc.storage_path, expiresInSeconds: 3600 })`.
       - `generateDocumentShareToken(documentId: string)`:
         - Generates 64-character random hex token (`crypto.randomBytes(32).toString('hex')`).
         - Inserts row into `document_share_tokens` with `expires_at = now() + 7 days`.
         - Returns shareable URL: `/reports/view?token=${token}`.
       - `deleteLabDocument(documentId: string)`:
         - Verifies tenant ownership; deletes storage object via `deleteFile()`; deletes database row; records audit log.
    4. Implement integration tests in `tests/labs/lab-documents.spec.ts`:
       - Test filename auto-amendment formatting.
       - Test MIME type and file size validation.
       - Test tenant isolation (ensuring Tenant B cannot fetch Tenant A's documents).
  </action>
  <acceptance_criteria>
    - `features/labs/` exports all required schemas and server actions.
    - Files are stored with auto-amended filenames adhering to `[Patient]_[Original]_[Date].ext`.
    - `tests/labs/lab-documents.spec.ts` passes.
  </acceptance_criteria>
