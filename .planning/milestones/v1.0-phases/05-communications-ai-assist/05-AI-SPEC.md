## 1. System Classification

**System Type:** Extraction / Structured Clinical Note Generation & Assistive Clinical Synthesis

**Description:**
Phase 5 provides clinician-assistive AI capabilities within the ClinicQ outpatient consultation workspace:
1. **Clinical SOAP Note Synthesis:** Converts unstructured doctor shorthand and voice dictation transcripts into structured SOAP clinical notes (Chief Complaints, Examination, Diagnosis, Advice).
2. **Returning Patient Catch-Up Summary:** Generates an on-demand 3-bullet executive clinical summary (previous diagnosis, active medications, chronic conditions/allergies) when opening a returning patient's file.
3. **Deterministic Prescription Sourcing:** Assistive prescription suggestions are strictly separated from stochastic LLM generation — queried deterministically from the doctor's own verified historical prescriptions (`visits.prescription`), guaranteeing zero hallucination.

**Critical Failure Modes:**
1. **Medical Hallucination / Fabricated Prescriptions:** AI introducing unapproved medications, wrong dosages, or non-existent clinical findings. *Mitigation: Prescription suggestions are purely deterministic historical SQL queries, never generated by LLM.*
2. **Auto-Finalization or Silent Record Overwrite:** AI notes replacing doctor input or auto-finalizing an encounter without clinician review. *Mitigation: Non-destructive draft insertion requiring explicit doctor click on "Accept & Insert" and standard sign-off.*
3. **Structured JSON Output Schema Drift:** LLM returning malformed markdown or partial JSON that crashes parser components. *Mitigation: Runtime Zod schema validation on structured JSON outputs with automated retry.*
4. **Vendor Lock-in & Provider Outage Halt:** Hardcoding proprietary vendor APIs halting clinical operations during provider outages. *Mitigation: Universal OpenAI-compatible REST specification (`baseURL`, `apiKey`, `model`) with fallback to local `MockAiProvider`.*

## 1b. Domain Context

**Industry Vertical:** Outpatient Clinical Healthcare (OPD Clinics in India — General Practice, Dental, Pediatrics).

**User Population:** Practicing doctors, clinicians, and reception staff in high-throughput outpatient clinics (typically 3–5 minutes per consultation).

**Stakes Level:** High (Clinical patient records and treatment guidance).

**Output Consequence:** Clinical notes generated by AI form part of the permanent legal medical record and patient prescription document once accepted and signed by the doctor.

### What Domain Experts Evaluate Against

| Dimension | Good (Expert Accepts) | Bad (Expert Flags) | Stakes | Source |
|-----------|----------------------|--------------------|--------|--------|
| **Clinical Factual Precision** | Faithfully reflects only symptoms, vitals, and findings explicitly provided in shorthand/dictation | Extrapolates unmentioned symptoms, creates phantom physical exam findings | Critical | Indian Medical Council Regulations & Good Clinical Practice |
| **Medical Terminology Normalization** | Expands common Indian OPD abbreviations accurately (e.g. "c/o c&c 3d" → "Cough and cold for 3 days"; "adv PCM" → "Paracetamol") | Misinterprets clinical shorthand into unrelated terms or wrong drug classes | High | Standard OPD Clinical Practice |
| **Format Integrity & SOAP Separation** | Clearly segregates Subjective complaints, Objective exam, Assessment, and Plan advice | Blends advice into complaints or puts medications into chief complaints | Medium | Standard SOAP Medical Record Format |
| **Hallucination-Free Prescriptions** | Suggests only what the doctor has actually prescribed in past encounters for the given diagnosis | Invents novel dosages, off-label regimens, or contraindicated medications | Critical | Patient Safety & NMC Guidelines |

### Known Failure Modes in This Domain
- **Phantom Vitals:** LLM inferring normal blood pressure or pulse when none was mentioned in the dictation.
- **Dosage Inversion:** Confusing frequency (e.g. interpreting "1-0-1" as "101 tablets").
- **Language Code-Switching Drop:** Dropping clinical context when speech input switches between English, Hindi, or Marathi terminology (e.g. "sar dard", "sardi khansi").

### Regulatory / Compliance Context
- **National Medical Commission (NMC) RMP Regulations:** Clinician bears sole legal responsibility for all signed prescriptions and notes. AI must remain strictly assistive; all outputs labeled "AI Suggested" until accepted.
- **DPDP Act 2023:** Patient clinical data sent to external AI APIs must minimize unnecessary personal identifiers (e.g. patient name/phone stripped from dictation prompts; only clinical tokens passed).

### Domain Expert Roles for Evaluation

| Role | Responsibility |
|------|---------------|
| Consultant Doctor (MBBS/MD) | Clinical accuracy validation, gold-standard shorthand test dataset labeling |
| Clinic Receptionist / Nurse | Usability and latency evaluation of dictation tools in real clinic workflow |

## 2. Framework Decision

**Selected Framework:** Universal OpenAI-Compatible API Gateway (`openai` SDK / Standard REST protocol)

**Version:** `openai` ^4.85.0 (or lightweight native Node.js fetch wrapper conforming to `/v1/chat/completions`)

**Rationale:**
1. **Universal Provider Interchangeability:** The OpenAI REST specification is the universal industry standard supported natively by **OpenAI**, **Google Gemini** (via official `/v1beta/openai/` endpoint), **Anthropic Claude** (via proxy or OpenRouter), **DeepSeek**, **Groq**, and self-hosted models (Ollama/vLLM).
2. **Zero Vendor Lock-In:** The company can switch from OpenAI to Gemini, Claude, or a local server by updating only three environment variables (`AI_BASE_URL`, `AI_API_KEY`, `AI_MODEL_NAME`) without touching a single line of codebase logic.
3. **Native TypeScript Support & Lightweight Footprint:** No heavy Python microservices or multi-megabyte orchestration frameworks required. Keeps the modular monolith fast, predictable, and directly deployable on Vercel/Next.js.

**Alternatives Considered:**

| Framework | Ruled Out Because |
|-----------|------------------|
| LangChain / LangGraph | Unnecessary abstraction layers, bloated dependency tree, frequent breaking changes, tightly couples business logic to LangChain idioms. |
| Direct Google Vertex / Anthropic SDK | Locks codebase to a single vendor's proprietary API format and SDK conventions. |
| Standalone Python FastAPI Service | Violates AGENTS.md §5 baseline modular monolith rule (Next.js server capabilities preferred unless specialized ML hardware is required). |

**Vendor Lock-In Accepted:** No. Zero vendor lock-in. Full protocol neutrality via OpenAI REST specification.

## 3. Framework Quick Reference

### Installation
```bash
npm install openai
```

### Core Imports
```typescript
import OpenAI from "openai";
import { z } from "zod";
```

### Entry Point Pattern (`lib/ai/gateway.ts`)
```typescript
import OpenAI from "openai";

const aiBaseUrl = process.env.AI_BASE_URL || "https://api.openai.com/v1";
const aiApiKey = process.env.AI_API_KEY || "";
const defaultModel = process.env.AI_MODEL_NAME || "gpt-4o-mini";

export const aiClient = new OpenAI({
  baseURL: aiBaseUrl,
  apiKey: aiApiKey || "dummy-key",
});

export async function generateStructuredCompletion<T>(params: {
  systemPrompt: string;
  userPrompt: string;
  schema: z.ZodSchema<T>;
  model?: string;
}): Promise<T> {
  const response = await aiClient.chat.completions.create({
    model: params.model || defaultModel,
    messages: [
      { role: "system", content: params.systemPrompt },
      { role: "user", content: params.userPrompt },
    ],
    response_format: { type: "json_object" },
    temperature: 0.2, // Low temperature for high factual precision
  });

  const content = response.choices[0]?.message?.content || "{}";
  const parsed = JSON.parse(content);
  return params.schema.parse(parsed);
}
```

### Key Abstractions

| Concept | What It Is | When You Use It |
|---------|-----------|-----------------|
| `AiGateway` (`lib/ai/`) | Central wrapper abstracting model calls | All AI features in the application consume this interface |
| `MockAiProvider` | Deterministic offline test double | Used in local dev, automated vitest runs, and CI/CD without API keys |
| `ZodSchemaParser` | Runtime type and schema validator | Validates every LLM JSON output before delivering to UI |

### Common Pitfalls
1. **JSON Markdown Wrapping:** Some models wrap JSON in ````json ... ```` fences even when `type: "json_object"` is requested. *Sanitize response content to strip markdown fences before `JSON.parse`.*
2. **Missing Shorthand Normalization:** Raw clinical transcripts may contain regional phrasing. *System prompt must include explicit few-shot normalization examples for common Indian medical shorthand.*
3. **Empty API Key in Development:** Running `new OpenAI()` without an API key throws initialization errors. *Check for presence of key; fallback seamlessly to `MockAiProvider` in dev.*

## 4. Implementation Guidance

**Model Configuration:**
- Default model: `gpt-4o-mini` (or `gemini-1.5-flash` / `claude-3-5-haiku` via proxy).
- Temperature: `0.1`–`0.2` (Strictly low temperature to eliminate creative fabrication).
- Max tokens: `1000` (More than sufficient for structured SOAP summaries; caps latency and cost).

**Core Pattern: SOAP Note Synthesis:**
Input: Unstructured shorthand / dictation text.
Output: Validated JSON matching `SoapDraftSchema`.
```typescript
export const SoapDraftSchema = z.object({
  chief_complaints: z.array(z.object({
    complaint: z.string(),
    duration: z.string().optional(),
  })),
  examination: z.string(),
  provisional_diagnosis: z.string().optional(),
  advice: z.string().optional(),
});
```

**Core Pattern: Returning Patient Catch-Up Summary:**
Input: Array of past visits (dates, diagnoses, prescribed medicines, recorded vitals).
Output: Validated JSON matching `CatchUpSummarySchema`.
```typescript
export const CatchUpSummarySchema = z.object({
  last_visit_summary: z.string(),
  active_medications: z.array(z.string()),
  alerts_and_chronic: z.array(z.string()),
});
```

## 4b. AI Systems Best Practices

### Structured Outputs with Zod & Pydantic Parity
Every AI call is bounded by a runtime Zod schema. If the LLM produces a schema mismatch, the gateway retries once with the parsing error appended to the prompt before failing gracefully.

### Prompt Engineering Discipline
- **System vs User Separation:**
  - *System prompt:* Enforces role boundaries: "You are a clinical transcription assistant for an Indian outpatient clinic. You convert doctor shorthand into structured notes. Do NOT invent findings or medications."
  - *User prompt:* Contains exclusively the dictation text and anonymized clinical bullet points.
- **Zero PII Exposure:** Patient names, phone numbers, and identifying demographic IDs are stripped before calling the AI gateway. Only age, gender, and clinical history tokens are passed.

### Cost and Latency Budget
- **On-Demand Only:** Catch-Up summaries and SOAP synthesis are triggered explicitly by clinician action (never called automatically on background page renders).
- **Cost Target:** Average prompt + completion < 800 tokens per consultation. At `gpt-4o-mini` / `gemini-1.5-flash` pricing, total AI cost is < ₹0.10 per encounter, easily sustainable within the ₹999/month subscription.
- **Latency Budget:** Target < 1.5 seconds for complete SOAP synthesis.

## 5. Evaluation Strategy

### Dimensions

| Dimension | Rubric (Pass/Fail) | Measurement Approach | Priority |
|-----------|--------------------|---------------------|----------|
| **Schema Conformance** | Output strictly parses against Zod schema without JSON errors (100% target) | Code (Automated Vitest) | Critical |
| **Factual Precision** | Output contains zero phantom symptoms or unstated physical findings | Ground-truth test suite (Code + LLM Judge) | Critical |
| **Shorthand Recall** | All complaints, durations, and advice in raw input are present in structured output (≥ 95%) | Automated comparison against labeled reference set | High |
| **Latency Budget** | End-to-end response delivered in < 2.0s on standard 4G/broadband | Automated latency benchmark | High |
| **Zero-Hallucination Rx** | Prescription suggestions are 100% matched to doctor history database | SQL deterministic test | Critical |

### Eval Tooling

**Primary Tool:** Vitest automated evaluation suite (`tests/ai/`) with labeled clinical benchmark cases.

**CI/CD Integration:**
```bash
npm run test tests/ai/
```
Runs deterministic evaluations and mock provider schema validation on every pull request.

### Reference Dataset
- **Size:** 25 curated Indian OPD clinical shorthand vignettes (GP, Pediatric, Dental scenarios).
- **Composition:**
  - 10 standard OPD cases (fever, URI, gastroenteritis, hypertension follow-up).
  - 5 pediatric cases with immunization and growth history.
  - 5 dental cases with dental shorthand.
  - 5 messy / noisy dictations with abbreviations and background speech artifacts.

## 6. Guardrails

### Online (Real-Time)

| Guardrail | Trigger | Intervention |
|-----------|---------|--------------|
| **Clinician Acceptance Gate** | Generated SOAP draft presented in UI | Notes never saved to active encounter until doctor clicks "Accept & Insert" |
| **Visible AI Labeling** | Any AI-derived draft displayed in cabin | Distinct `✦ AI Suggested Draft` badge in UI |
| **Schema Validation Fallback** | Malformed JSON returned from LLM | Raw doctor shorthand preserved in textarea; alert banner shown with Retry button |
| **Deterministic Rx Boundary** | Doctor enters diagnosis in prescription builder | Prescriptions loaded strictly via SQL from doctor's signed past visits; LLM is never queried |

### Offline (Regression & Quality)

| Metric | Sampling Strategy | Action on Degradation |
|--------|------------------|----------------------|
| **Shorthand Extraction Accuracy** | Evaluated on 25-case benchmark in CI | Block build if accuracy drops below 95% |
| **API Error & Timeout Rate** | Monitored in production logs | Alert if failure rate > 2% over 1-hour window |
