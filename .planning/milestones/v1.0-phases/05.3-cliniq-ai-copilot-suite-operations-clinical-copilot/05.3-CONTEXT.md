# Phase 05.3: CliniQ AI Copilot Suite — Operations & Clinical Copilot - Context

**Gathered:** 2026-10-28  
**Status:** Ready for planning  

<domain>
## Phase Boundary

Phase 05.3 delivers the full CliniQ AI vision (`docs/ai-vision.md`) consisting of two complementary AI capabilities sharing a unified, secure foundation:

1. **Global Operations Copilot (Shell-Wide):**
   - Accessible from anywhere in the application via a top-header button or `Cmd+K` keyboard shortcut as a 420px slide-over right drawer (full-width on mobile), keeping background context visible.
   - Built with the open-source Vercel AI SDK (`useChat`) for streaming logic and state management, paired with custom Radix UI primitives and TailAdmin design tokens adhering strictly to `DESIGN.md` (light-only theme, `#1769E0` primary brand color, crisp bordered cards, high WCAG contrast).
   - Core Tool Actions: Patient search, doctor availability lookup, appointment booking, rescheduling, cancellation (with instant calendar slot release), today's queue/appointments overview, and grounded product/workflow Q&A.
   - Inline interactive action confirmation cards showing structured details (Patient, Slot, Doctor, Fee) with `[Confirm]` and `[Cancel]` buttons that morph into a locked status badge upon execution.
   - Ambiguity resolution via interactive patient disambiguation chips (+91 E.164 phone, Age/Gender, Last Visit) and smart conflict recovery cards with alternative slot chips.
   - Inline quick patient registration for new patients during booking.
   - Token-frugal conversation management: sliding-window message pruning (sending only the last 4–6 turns to the LLM) and concise 1-line route context without heavy DOM or database dumps.

2. **Consultation Clinical Copilot (Doctor Cabin):**
   - Surfaced inside the Doctor Cabin (`app/(dashboard)/cabin/`), hidden by default to preserve a clean, distraction-free clinical UI, and opened as a right-hand sidebar panel upon clicking a dedicated "AI Assistant / Copilot" toolbar button.
   - Note structuring from doctor's shorthand into SOAP drafts (Chief Complaints, Examination, Advice) with granular section-by-section `[Insert]` buttons plus an `[Insert All]` action (with Append vs Replace choices if fields already contain text).
   - On-demand returning patient catch-up summaries (3 clinical bullets based on previous visits).
   - Context-aware ICD-10 coding assistance with ranked candidate cards, official WHO descriptions, and 1-line differential criteria bullets ("When to choose") with a 1-click `[Apply as Diagnosis]` chip.
   - Open-ended free-text clinical Q&A allowing doctors to ask reference questions, answered using medical knowledge and optional web search grounding, accompanied by a mandatory, prominent clinical disclaimer: *"⚠️ Clinical Advisory: CliniQ AI is an informational assistant, not a licensed healthcare professional. All information must be evaluated and verified under independent clinical judgment."*
   - Strict patient privacy: direct PII (Name, Phone, Aadhaar/ABHA, Address) is stripped before LLM ingestion; only de-identified parameters (Age, Sex, Vitals, Chronic Conditions, shorthand notes) are transmitted.
   - Clinical provenance tracking: `metadata.ai_assisted = true` and `ai_sections_used` stored on the visit record; final signed prescription and PDF remain 100% clean without AI badges.

3. **Explicit Scope Guardrails & Boundaries:**
   - **Zero Autonomous Prescribing:** Medication Decision Support and automated drug-drug interaction checking are explicitly omitted. Prescribing remains 100% clinician-driven with the existing deterministic historical prescription chips from Phase 5.
   - **Role-Based Access Control (RBAC):** Nurses can view visit records, manage appointments/queue, and record vitals, but cannot modify clinical visit records. Doctors and Nurses cannot change administrative settings (billing configuration, staff invites, tenant config - reserved for Clinic Owner/Admin). Copilot tools strictly enforce these server-side boundaries.
   - **Ambient Voice Listening:** Microphone selection, audio recording, speaker diarization, and continuous consultation listening are deferred to post-launch per `docs/ai-vision.md`.

</domain>

<decisions>
## Implementation Decisions

### 1. Operations Copilot UX & Shell Placement
- **D-01: Slide-Over Right Drawer with Header Icon & Cmd+K Shortcut:** — **Reversibility:** costly — application shell layout.
  - The Global Operations Copilot is anchored as a 420px slide-over right drawer (full-width on mobile) opened via a top-header robot/sparkle icon and `Cmd+K` keyboard shortcut. Mirrors the in-app notification center drawer, keeping active page content visible in the background.
- **D-02: Vercel AI SDK (`useChat`) with TailAdmin & Radix UI Primitives:** — **Reversibility:** costly — frontend chat architecture.
  - Chat engine standardizes on open-source `@ai-sdk/react` (`useChat`) for streaming logic, optimistic updates, and tool call handling. Visual rendering uses native Radix UI primitives and TailAdmin tokens adhering strictly to `DESIGN.md` (light-only theme, `#1769E0` primary brand accent, `#F8FAFC` canvas, crisp bordered action cards).
- **D-03: Interactive Inline Action Confirmation Cards:** — **Reversibility:** reversible — chat message component.
  - Actions like appointment booking, rescheduling, and cancellation render an interactive card inside the chat stream showing structured parameters (Patient, Doctor, Slot, Fee) with `[Confirm Booking]` and `[Cancel]` buttons. Upon confirmation, buttons lock and morph into a green "Confirmed" status badge with a direct link to the record, preventing duplicate submissions.
- **D-04: Token-Frugal Conversation Persistence & Sliding Window:** — **Reversibility:** reversible — client state management.
  - Conversation thread persists in client session state across page navigation, with an instant "New Chat / Clear" button. To minimize token waste, the client implements sliding-window pruning: only the last 4–6 message turns are sent in the API request payload (older messages remain in the UI scrollback). Screen context is transmitted as a compact 1-line metadata header (`role`, `screen`, `selected_date`) rather than heavy page or database dumps.

### 2. Operations Copilot Tool Scope & Ambiguity Resolution
- **D-05: Full Core Operational Tool Set:** — **Reversibility:** costly — server-side tool definitions.
  - Supported tool inventory:
    1. `search_patients` (name, phone)
    2. `check_availability` (doctor_id, date)
    3. `book_appointment` (patient_id, doctor_id, date, start_time, type, reason) -> triggers preview card
    4. `reschedule_appointment` (appointment_id, new_date, new_start_time) -> triggers preview card
    5. `cancel_appointment` (appointment_id, reason) -> triggers preview card & releases calendar slot
    6. `get_queue_status` / `get_today_appointments` (doctor_id, date, status)
    7. `get_product_help` (grounded in verified product manifest)
- **D-06: Interactive Patient Disambiguation Chips:** — **Reversibility:** reversible — tool response card.
  - When a name search returns multiple matches, Copilot renders clickable candidate chips displaying Patient Name, normalized +91 Phone, Age/Gender, and Last Visit date. Clicking a chip locks the patient identity and seamlessly resumes the requested workflow.
- **D-07: Inline Conflict Recovery with Smart Alternatives:** — **Reversibility:** reversible — scheduling tool UX.
  - If a slot becomes unavailable between preview and confirmation (or is conflicting), Copilot renders an inline conflict card explaining the issue (e.g. "10:30 AM was just taken") and immediately presents the next 2–3 available alternative slot chips with 1-click rebooking.
- **D-08: Grounded Product Knowledge Base & FAQ Manifest:** — **Reversibility:** reversible — documentation asset.
  - Product Q&A is grounded in a curated, in-repo feature and navigation manifest (`lib/ai/knowledge/product-manifest.ts`). The Copilot gives exact step-by-step instructions based on actual ClinicOS screens, preventing hallucinations of nonexistent capabilities.
- **D-09: Explicit Role Policy & Server-Side RBAC Enforcement:** — **Reversibility:** one-way — security boundary.
  - Tool execution enforces exact clinic roles:
    - **Nurses:** Can view visit records, manage appointments/queue, and record vitals, but cannot modify clinical visit records.
    - **Doctors & Nurses:** Unrestricted for everyday clinical/queue operations, but strictly blocked from modifying Administrative settings (clinic billing rates, staff invites, tenant config - reserved for Clinic Owner/Admin).
    - If an unauthorized action is requested, Copilot politely explains the permission boundary.
- **D-10: Inline Quick Patient Registration:** — **Reversibility:** costly — patient service integration.
  - If an intended patient is not registered, Copilot gathers Name, +91 Mobile, and Gender/Age, creates the tenant-isolated patient record, and presents a combined registration + appointment confirmation card in a single seamless flow.
- **D-11: Strict Doctor Shift Adherence with Intentional Override Warning:** — **Reversibility:** reversible — appointment booking validation.
  - Booking tools validate against doctor shifts, break hours, and blocked leave from Phase 03.3. If staff explicitly requests an overbook or squeeze-in outside shift hours, the confirmation card displays a visible "Schedule Warning: Outside active shift" badge requiring intentional confirmation.
- **D-12: AI Action Auditing via `audit_logs`:** — **Reversibility:** costly — audit schema.
  - Actions executed through Copilot use standard audit event types (`appointment_booked`, `appointment_cancelled`, `patient_created`) with `actor_id = confirming_user_id` and structured metadata `metadata.channel = 'operations_copilot'` and `metadata.prompt`, ensuring complete transparency and compliance.

### 3. Clinical Copilot Cabin Workspace Integration
- **D-13: Hidden-by-Default Right-Hand Panel in Doctor Cabin:** — **Reversibility:** costly — cabin layout.
  - In the Consultation Cabin (`app/(dashboard)/cabin/`), the Clinical Copilot is hidden by default to keep the consultation interface clean and focused. It opens as a right-hand sidebar panel (docked on desktop, full-screen drawer on mobile) only upon clicking a dedicated "AI Assistant / Copilot" button in the cabin header.
- **D-14: Granular SOAP Draft Section Insertion with `[Insert All]`:** — **Reversibility:** reversible — cabin form integration.
  - Generated SOAP drafts render structured cards for Chief Complaints, Examination, Diagnosis Hypothesis, and Advice. Each section features an individual `[Insert]` button alongside a top `[Insert All]` button. If the target field already contains doctor notes, a quick toggle prompt allows Appending or Replacing text.
- **D-15: Strict Patient De-identification & Privacy Sanitization:** — **Reversibility:** one-way — privacy & DPDP compliance.
  - Direct identifiers (Patient Name, Phone, Aadhaar/ABHA, Address) are scrubbed before payload transmission. Only de-identified parameters (Age, Sex, Vitals, Chronic Conditions list, and doctor's shorthand notes) are provided to the LLM.
- **D-16: Clinical Provenance Metadata Tracking:** — **Reversibility:** costly — visit schema.
  - When an AI draft is accepted, `metadata.ai_assisted = true` and `ai_sections_used = [...]` are saved to the visit record. The finalized prescription PDF and patient-facing documents remain completely clean without AI watermarks, reflecting doctor verification and sign-off.

### 4. ICD-10 Coding Assistance & Clinical Reference Q&A
- **D-17: Context-Aware ICD-10 Coding Helper:** — **Reversibility:** reversible — clinical coding helper.
  - Doctors can ask freeform coding questions in the Clinical Copilot ("ICD-10 code for migraine with aura") or click a "Suggest ICD Codes" button on the Diagnosis field. Copilot displays the top 2–4 candidate cards with code, official WHO description, and a 1-click `[Apply as Diagnosis]` chip.
- **D-18: Differential Criteria Bullets for Code Ambiguity:** — **Reversibility:** reversible — coding prompt design.
  - When candidate codes have multiple specific variants, candidate cards present a 1-line "When to choose" distinction (e.g. site, severity, acute vs chronic, with/without complication) allowing immediate clinical selection without consulting external code books.
- **D-19: Open-Ended Free-Text Clinical Q&A with Mandatory Disclaimer:** — **Reversibility:** reversible — clinical chat response.
  - Doctors can ask any freeform clinical reference questions in the cabin Copilot. The LLM provides informative answers using medical knowledge and optional web search grounding. Every clinical response features a mandatory, persistent disclaimer: *"⚠️ Clinical Advisory: CliniQ AI is an informational assistant, not a licensed healthcare professional. All information must be evaluated and verified under independent clinical judgment."*
- **D-20: Omission of Medication Decision Support:** — **Reversibility:** one-way — scope boundary.
  - Automated medication decision support, drug-drug interaction warnings, and LLM prescription checking are explicitly excluded from this release. Prescribing remains 100% human-directed, supported exclusively by the deterministic historical prescription chips from Phase 5 (`D-20`).

## Specific Ideas

- **Token Discipline:** To prevent burning tokens, the Operations Copilot strictly limits LLM context to the last 4–6 turns via sliding window pruning, and passes only a concise 1-line route metadata header.
- **Grounded Product Help:** The Copilot answers product questions using a structured in-repo manifest of real ClinicOS screens and features, preventing hallucinated workflows.
- **Clinical Advisory Disclaimer:** Every clinical reference response carries the mandatory disclaimer: *"⚠️ Clinical Advisory: CliniQ AI is an informational assistant, not a licensed healthcare professional. All information must be evaluated and verified under independent clinical judgment."*
- **Clean Consultation Screen:** Clinical Copilot remains hidden by default to keep the Doctor Cabin interface uncluttered and distraction-free, opening only when explicitly clicked.
