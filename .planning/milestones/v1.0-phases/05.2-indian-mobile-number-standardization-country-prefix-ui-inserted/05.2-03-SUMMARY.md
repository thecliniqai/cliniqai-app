## 4. Key Design Decisions & Deviations

1. **Prefix-Tolerant Subscriber Matching:** In both `buildPatientSearchFilter` and `getClinicVisitsRegister`, when `digitsOnly.startsWith("91") && digitsOnly.length >= 5`, the subscriber digits (`digitsOnly.slice(2)`) are extracted and matched alongside the full string. This ensures users searching with or without `+91` or `91` seamlessly locate records.
2. **Async Export of `buildPatientSearchFilter`:** Because `features/patients/actions.ts` is designated `"use server"`, helper functions exported from it must be `async`. Exporting `buildPatientSearchFilter` as an `async function` allows direct testing and reuse while adhering strictly to Next.js server actions bundling constraints.
3. **Strict Minimum Digit Threshold ($\ge 3$ Digits):** To mitigate potential Denial of Service (T-05.2-09) and prevent sequential full-table scans on 1- or 2-character inputs, phone search expansion only triggers when the extracted digits have a length of 3 or more.
4. **Sanitization against PostgREST Injections (T-05.2-07):** Delimiter characters `,`, `(`, and `)` are replaced with whitespace before constructing PostgREST `.or(...)` filter clauses, preventing injection attacks.
