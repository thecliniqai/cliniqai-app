## 1. Executive Summary

In Indian OPD clinics, mobile numbers are the primary identifier for patients and the exclusive channel for WhatsApp reminders, prescriptions, invoices, and tokenized sharing. Previously, raw `<input type="tel">` and text fields allowed arbitrary strings, missing country codes, 8-digit partials, or conflicting prefixes (`+91`, `91`, `0`).

Phase 05.2 standardizes mobile number handling from end-to-end:
1. **Frontend Presentation:** A reusable, accessible `PhoneInput` component (`components/ui/phone-input.tsx`) featuring an inset Indian flag (`🇮🇳`), fixed `+91` badge with divider line, real-time numeric filtering, and auto-formatting up to 10 digits.
2. **Validation Layer:** Enforces valid Indian mobile numbers (`/^[6-9]\d{9}$/`) across frontend forms and backend Zod schemas.
3. **Database Layer:** Standardizes storage format to international ITU-T E.164 (`+91XXXXXXXXXX`), with an idempotent migration (`000017_normalize_indian_phone_numbers.sql`) updating existing rows.
4. **Search Layer:** Allows flexible searching by 10 digits or partial numbers without requiring users to type `+91`.

## 2. Core Architecture & Utility Design

### 2.1 Indian Phone Number Formatting Specifications

Indian mobile phone numbers conform to the National Numbering Plan (NNP):
- Total subscriber digits: 10 digits.
- Valid initial digits: `6`, `7`, `8`, or `9`. (Numbers starting with `0`, `1`, `2`, `3`, `4`, `5` are landlines, toll-free, or invalid).
- Standard Regular Expression:
  ```typescript
  export const INDIAN_MOBILE_REGEX = /^[6-9]\d{9}$/;
  ```

### 2.2 Normalization & Extraction Functions (`lib/utils/phone.ts`)

A central phone utility handles all format conversions:

```typescript
/**
 * Strips all non-digit characters and extracts the 10-digit Indian subscriber number.
 * Handles inputs formatted as:
 * - "+919876543210" -> "9876543210"
 * - "919876543210"  -> "9876543210"
 * - "09876543210"   -> "9876543210"
 * - "98765-43210"   -> "9876543210"
 */
export function extractTenDigits(phone: string | null | undefined): string {
  if (!phone) return "";
  const digits = phone.replace(/\D/g, "");
  if (digits.length === 10) return digits;
  if (digits.length === 11 && digits.startsWith("0")) return digits.slice(1);
  if (digits.length === 12 && digits.startsWith("91")) return digits.slice(2);
  if (digits.length > 10) return digits.slice(-10);
  return digits;
}

/**
 * Normalizes input to international ITU-T E.164 format (+91XXXXXXXXXX).
 * Throws or returns empty if not a valid 10-digit Indian mobile number.
 */
export function toE164(phone: string | null | undefined): string {
  const digits = extractTenDigits(phone);
  if (digits.length === 10 && INDIAN_MOBILE_REGEX.test(digits)) {
    return `+91${digits}`;
  }
  return phone?.trim() || "";
}

/**
 * Formats a 10-digit number for display with standard grouping (5+5):
 * "9876543210" -> "98765 43210"
 */
export function formatTenDigitsDisplay(phone: string): string {
  const digits = extractTenDigits(phone);
  if (digits.length <= 5) return digits;
  return `${digits.slice(0, 5)} ${digits.slice(5, 10)}`;
}

/**
 * Validates whether the given string is a valid Indian mobile number.
 */
export function isValidIndianMobile(phone: string | null | undefined): boolean {
  if (!phone) return false;
  const digits = extractTenDigits(phone);
  return digits.length === 10 && INDIAN_MOBILE_REGEX.test(digits);
}
```

## 3. UI Component Architecture (`PhoneInput`)

### 3.1 Styling & Composition
Conforms strictly to `DESIGN.md` light-only rules:
- **Outer Box:** Uses `focus-within:border-[#1769E0] focus-within:ring-2 focus-within:ring-[#1769E0]/20` around the entire flex container so the flag, prefix, and input feel like one seamless input element.
- **Left Badge:** Light gray inset (`bg-gray-50/80`), subtle right divider (`border-r border-gray-200`), containing the Indian flag (`🇮🇳`) and `+91` text (`text-gray-700 font-semibold text-sm`).
- **Input Field:** `type="tel"`, `inputMode="numeric"`, `placeholder="98765 43210"`, `maxLength={10}`. No internal borders or outlines.
- **Copy-Paste Handler:** Normalizes pasted strings immediately via `extractTenDigits(pastedText)` to prevent accidental paste errors from Truecaller or WhatsApp.

## 4. Database Migration (`000017_normalize_indian_phone_numbers.sql`)

### 4.1 SQL Normalization Strategy
An idempotent migration cleans historical data across all phone columns:

```sql
-- 1. Helper function to normalize Indian phone numbers to E.164
CREATE OR REPLACE FUNCTION normalize_indian_phone_e164(raw_phone TEXT)
RETURNS TEXT AS $$
DECLARE
    digits TEXT;
BEGIN
    IF raw_phone IS NULL OR trim(raw_phone) = '' THEN
        RETURN raw_phone;
    END IF;

    -- Strip non-digits
    digits := regexp_replace(raw_phone, '\D', '', 'g');

    -- If 12 digits starting with 91
    IF length(digits) = 12 AND digits LIKE '91%' THEN
        digits := substring(digits FROM 3);
    -- If 11 digits starting with 0
    ELSIF length(digits) = 11 AND digits LIKE '0%' THEN
        digits := substring(digits FROM 2);
    END IF;

    -- If exactly 10 digits, format as E.164 (+91XXXXXXXXXX)
    IF length(digits) = 10 THEN
        RETURN '+91' || digits;
    END IF;

    -- Fallback to original trimmed phone if length is non-standard
    RETURN trim(raw_phone);
END;
$$ LANGUAGE plpgsql IMMUTABLE;

-- 2. Clean existing tables
UPDATE patients
SET phone = normalize_indian_phone_e164(phone)
WHERE phone IS NOT NULL AND phone NOT LIKE '+91%';

UPDATE staff_members
SET phone = normalize_indian_phone_e164(phone)
WHERE phone IS NOT NULL AND phone NOT LIKE '+91%';

UPDATE clinics
SET phone = normalize_indian_phone_e164(phone)
WHERE phone IS NOT NULL AND phone NOT LIKE '+91%';

UPDATE communication_queue
SET recipient_phone = normalize_indian_phone_e164(recipient_phone)
WHERE recipient_phone IS NOT NULL AND recipient_phone NOT LIKE '+91%';
```
