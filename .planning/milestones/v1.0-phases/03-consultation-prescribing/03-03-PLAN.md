<objective>
Build the diagnosis selector and electronic prescription builder for Phase 3:
1. Diagnosis workflow: Terminology search over curated Indian OPD catalog (ICD-11 & SNOMED CT), specialty quick chips, custom diagnosis auto-save, inline diagnosis remarks, and chronic condition profile sync.
2. Electronic Prescription Builder: CDCI drug search with doctor favorites prioritized, custom medicines on-the-fly, 1-tap Indian OPD dosage chips (`1-0-1`, `After food`, `5d`), allergy awareness banner, and protocol templates.
3. Server Actions (`features/terminology/actions.ts`, `features/prescriptions/actions.ts`) with strict multi-tenant RLS, input bounds checking, and audit logging.
4. Comprehensive testing: Unit tests for dosage chips parsing (`tests/prescriptions/dosage.spec.ts`) and integration tests for full consultation progression (`tests/integration/consultation-flow.spec.ts`).
</objective>

<threat_model>
| Threat ID | Category | Component | Description | Severity | Mitigation |
|-----------|----------|-----------|-------------|----------|------------|
| T-03-06 | Integrity / Patient Safety | `features/prescriptions/actions.ts` | Tampered dosage, frequency, or duration inputs resulting in dangerous medication instructions. | high | Enforce strict Zod schema validation on dosage, frequency enum/patterns, duration strings, and sanitize all medication strings. |
| T-03-07 | Multi-Tenancy / Data Leakage | `doctor_custom_medicines` & `doctor_custom_diagnoses` | Clinic A doctor accessing or modifying custom drugs/diagnoses belonging to Clinic B. | high | Enforce tenant isolation via `current_user_tenant_ids()`, doctor ownership checks (`doctor_id = auth.uid()`), and parameterized queries. |
</threat_model>

    1. Create `features/terminology/schema.ts`:
       - `searchDiagnosesSchema`: query string (min 1), specialty (optional), limit (default 20).
       - `addConsultationDiagnosisSchema`: visit_id (UUID), patient_id (UUID), diagnosis_name (string min 1), snomed_concept_id (optional string), icd11_code (optional string), is_custom (boolean default false), is_chronic (boolean default false), notes (optional string max 500).
    2. Create `features/terminology/actions.ts`:
       - `searchDiagnoses(input, clientOverride?, sessionOverride?)`: queries `opd_diagnoses` using pg_trgm fuzzy matching; combines with `doctor_custom_diagnoses` for active doctor; returns ranked results with ICD-11 & SNOMED CT badges.
       - `addConsultationDiagnosis(input)`: verifies permission, checks tenant ownership, inserts into `consultation_diagnoses`. If `is_custom` is true, upserts into `doctor_custom_diagnoses`. If `is_chronic` is true, appends condition to `patients.chronic_conditions` text array.

       - `updateDiagnosisNote(diagnosisId, notes)`: updates optional inline clinical comment on diagnosis row.
    3. Create `components/consultation/diagnosis-section.tsx`:
       - Specialty quick chips: Top 6-8 frequent diagnoses for active specialty (e.g. for GP: Acute URTI, Viral Fever, Acute Gastroenteritis, Essential Hypertension, Type 2 DM, Acute Bronchitis; for Dental: Dental Caries, Gingivitis, Pulpitis, Periodontitis; for Peds: Viral URI, Acute Bronchiolitis, Acute Otitis Media, Febrile Convulsion).
       - Fast search dropdown showing clinical term with subtle ICD-11 / SNOMED CT code badges.
       - Table of selected diagnoses: diagnosis name, code badge, inline `+ Add Note` button, `Add to Chronic List` toggle checkbox, and remove button (`aria-label="Remove diagnosis"`).

    2. Create `features/prescriptions/actions.ts`:
       - `searchMedicines(query, doctorId, tenantId)`: calls `search_medicines` database RPC, prioritizing `doctor_custom_medicines` followed by CDCI search results.

       - `saveDoctorProtocolTemplate(template)`: saves current medication set as named template in `doctor_prescription_templates`.
       - `getDoctorProtocolTemplates(specialty)`: returns doctor's saved templates for the specialty.
