<objective>
Enhance the Calendar View, Doctor Timeline, and Booking Drawers:
1. Add interactive doctor filter pills in `components/calendar/calendar-view.tsx` with `[All Doctors]` and individual doctor pills for multi-select and single-select column filtering.
2. Upgrade `components/calendar/doctor-timeline.tsx` to dynamically compute start and end time boundaries based on active doctor shifts for the date (e.g., 08:00 to 21:00) rather than hardcoded 9 to 6.
3. Visually render off-duty intervals and blocked times with distinct diagonal hatching, dimmed background, and status tooltips/labels.
4. Implement `SoftBlockOverrideDialog` in `components/calendar/soft-block-override-dialog.tsx` enabling authorized staff to proceed with an emergency booking during off-duty/blocked times.
5. Upgrade `BookingDrawer` and `WalkInDrawer` with clean doctor names, dynamic slot duration pre-selection per doctor, and multi-slot reservation logic.
6. Verify the entire end-to-end scheduling and calendar experience with automated integration tests in `tests/integration/calendar-scheduling-ux.spec.ts`.
</objective>

<threat_model>
| Threat ID | Category | Component | Description | Severity | Mitigation |
|-----------|----------|-----------|-------------|----------|------------|
| T-03.3-05 | Double Booking / Slot Tampering | Multi-slot booking | Concurrent bookings creating overlapping appointments across 30m/45m multi-slot appointments. | high | Use transactional checks in `bookAppointment` with overlap formula `startA < endB && endA > startB` across the full multi-slot duration. |
| T-03.3-06 | Unauthorized Emergency Override | `SoftBlockOverrideDialog` | Non-staff users bypassing doctor blocks without logging or justification. | medium | Require emergency reason text, record override metadata in `audit_logs`, and verify `appointments:create` permission. |
</threat_model>

<tasks>
1. **Doctor Filter Pills in `components/calendar/calendar-view.tsx`**:
   - Add state `selectedDoctorIds: string[]` defaulting to `["all"]`.
   - Render horizontal pill bar above the calendar grid:
     - `[ All Doctors (N) ]`
     - Per-doctor pills: `[ Dr. {name} ({specialty}) ]` with doctor avatar/initials.
   - Clicking `All` selects all doctors.
   - Clicking an individual doctor filters to that doctor. Shift/Ctrl-clicking or toggling individual pills allows multi-doctor comparison.
   - Add a `[ + Block Time ]` secondary action button in the calendar toolbar opening `BlockTimeModal`.

2. **Dynamic Timeline & Shift Rendering in `components/calendar/doctor-timeline.tsx`**:
   - Calculate earliest shift start hour and latest shift end hour across all visible doctors for the current date.
   - Fallback to minimum 08:00 and maximum 20:00 (or up to 21:30 if late shifts exist).
   - Generate time slots dynamically for that span.
   - Per doctor column and slot:
     - Evaluate if time slot falls inside doctor's active shift (e.g., 10:00–13:00 or 17:00–21:00). If outside, mark `isOffDuty`.
     - Evaluate if slot falls inside an active `ScheduleBlock`. If so, mark `isBlocked` with `reason`.
     - Render off-duty slots with subtle dimmed background and muted text ("Off Duty").
     - Render blocked slots with diagonal stripe pattern, amber/gray badge, and block reason (e.g. "On Leave", "Surgery").
     - For visits spanning >15 minutes (e.g. 30m or 45m), render an elongated card spanning consecutive slots or display clean multi-slot duration indicator.

3. **Soft-Block Emergency Override Dialog in `components/calendar/soft-block-override-dialog.tsx`**:
   - When a user clicks a slot that is off-duty or blocked:
     - Render warning modal: "Doctor is Off Duty / Blocked at this time".
     - Displays doctor's working shifts for today and reason for block if applicable.
     - Offers an "Emergency Override" button requiring a brief emergency justification note.
     - On confirmation, opens `BookingDrawer` with `is_overbooked: true` or `override_reason`.

4. **Booking Drawer & Walk-In Drawer Updates (`booking-drawer.tsx` & `walk-in-drawer.tsx`)**:
   - Replace any UUID doctor name rendering with resolved doctor names and specialty tags.
   - When doctor selection changes in `BookingDrawer`:
     - Look up doctor's `default_slot_duration_minutes` (e.g. 45 min for dentist, 15 min for GP).
     - Auto-set `duration` state to that default value.
     - Ensure the duration dropdown includes: 15m, 20m, 30m, 45m, 60m, 90m.
   - In `WalkInDrawer`, ensure doctor selection uses clean resolved names.

5. **Integration Tests in `tests/integration/calendar-scheduling-ux.spec.ts`**:
   - Test calendar filtering: selecting a single doctor filters columns to 1; selecting "All" renders all doctors.
   - Test dynamic timeline: early morning (8:00 AM) and late evening (9:00 PM) shifts are rendered.
   - Test booking duration pre-fill: selecting dentist auto-populates 45m; selecting GP auto-populates 15m.
   - Test soft-block override workflow: off-duty slot prompts override dialog; valid emergency confirmation books appointment successfully.
</tasks>
