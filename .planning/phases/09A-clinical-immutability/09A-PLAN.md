# V2-09a Clinical immutability & amendment: plan

## Goal

After sign-off, what was signed cannot change. Not through PostgREST by any role, not through a SECURITY DEFINER function, not
through the service role, not by uploading the PDF a second time or deleting it. The one way to change a signed consultation is an
amendment: the doctor reopens it with a reason (the database snapshots the signed version), edits, and finalizes (the next version is
signed, the amended prescription is re-issued as an event, a new PDF is archived once and hashed). The workspace shows a signed
consultation read-only with an Amend action, so the amendment path is reachable and tested end to end. Lab documents are append-only.
Every rule is enforced by the database and the storage policies; the app only explains it.

Tracer: 09A-01 starts with the narrowest end-to-end slice (a service-role UPDATE of a signed visit's clinical note: migration, pgTAP,
Vitest DB case, fixed service text) and only then expands to the other tables, so an architectural dead end shows up after one commit.

## Shared rules for every plan

- Triggers: `SET search_path = ''`, every name schema-qualified, EXECUTE revoked from PUBLIC, anon, authenticated, service_role; BEFORE ROW; refusals SQLSTATE 42501 with a fixed name and no row data; names ordered so existing triggers keep their relative order (`prescription_items_fill_tenant` before `prescription_items_integrity_guard`; `visits_integrity_guard` before `visits_status_transition_guard`). A replaced function body starts from the LATEST definition (`grep -n "FUNCTION <name>" supabase/migrations/*.sql`) and changes only what the plan names; the diff against it is part of the review.
- Commands that are replaced (`step_sign_consultation`, `finalize_visit_amendment`) keep the V2-07 pattern unchanged: guard block, claim, lock, in-transaction audit and outbox, `lock_timeout = '2s'`, `search_path = ''`, EXECUTE for `authenticated` only.
