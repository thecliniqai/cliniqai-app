       - `--dry-run`: Preview all 13 template payloads without making HTTP calls.

       - `--authkey=<KEY>`: Override auth key.
       - `--number=<NUM>`: Override integrated WhatsApp number.
    2. Implement `inspectTemplateStatus(authKey: string, integratedNumber: string)`:
       - Endpoint: `GET https://control.msg91.com/api/v5/whatsapp/get-template-client/${integratedNumber}`
       - Headers: `authkey: authKey`, `Accept: application/json`.
       - If API returns non-200 or error, log clear diagnostic message.
       - Parse response templates (array of objects with `template_name` or `name`, `status`, `language`, `category`, `id` or `template_id`, `reason`):
         - Match each of the 13 local templates in `WHATSAPP_TEMPLATES`:
           - Find matching remote entry by `template_name`.
           - Classify status:
             - If found: `status.toUpperCase()` (e.g. `APPROVED`, `PENDING`, `REJECTED`, `PAUSED`).
             - If not found: `NOT SUBMITTED`.
         - Format terminal output with ASCII/Unicode status table:
           - Columns: `#`, `Template Name`, `Category`, `Language`, `Meta Status`, `Remote ID / Notes`.
           - Highlight approved status in green, pending in yellow, rejected in red.
           - Provide summary count (e.g. `Approved: 13/13`).
    3. Update default submission flow:
       - Use endpoint `https://control.msg91.com/api/v5/whatsapp/client-panel-template/`.
       - Log progress for all 13 templates with delay between requests to respect rate limits.
    4. Provide modular exports (e.g. `syncTemplates`, `fetchTemplateStatuses`) so functions can be unit-tested cleanly in Vitest.
  </action>
