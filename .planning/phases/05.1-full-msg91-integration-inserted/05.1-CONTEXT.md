**Gathered:** 2026-10-27

<domain>
## Phase Boundary

Phase 05.1 integrates MSG91 as the primary production communications gateway for ClinicOS, with an immediate operational focus on **WhatsApp**:
1. **Production MSG91 WhatsApp Provider (`lib/messaging/providers/msg91.ts`):** Complete adapter supporting outbound pre-approved template messages via MSG91 `template-bulk` endpoint (`https://control.msg91.com/api/v5/whatsapp/whatsapp-outbound-message/bulk/`), mapping positional parameters (`{{1}}`, `{{2}}`, etc.), quick reply buttons (`Confirm`, `Cancel`, `Reschedule`), and tokenized document URL buttons (`View Prescription`, `View Receipt`, `View Report`).
2. **Pre-Approved WhatsApp Template Catalogue & CLI Sync (`lib/messaging/templates/`):** Complete repository file `whatsapp-templates.json` matching MSG91's `create-whatsapp-template` OpenAPI schema for all 13 clinical and operational events, accompanied by `npm run msg91:sync-templates` for automated submission and status inspection.
3. **Inbound Two-Way Webhook & Delivery Reports (DLR) (`/api/webhooks/messaging/msg91`):** Inbound webhook handler processing patient button replies (`[Confirm]`, `[Cancel]`, `[Reschedule]`), auto-releasing calendar slots on cancellation, generating tokenized reschedule links, executing conversational triage auto-replies with front-desk notification alerts, and capturing MSG91 delivery report webhooks (`delivered`, `read`, `failed`) to update `communication_queue` status.
4. **Centralized Platform WABA & DevLogger Fallback:** Centralized ClinicQ verified WhatsApp sender number for all clinics with dynamic clinic branding, backed by `DevLoggerProvider` in development/testing when MSG91 credentials are not present.

*Note on Phase Scope:* SMS Flow API and SendOTP/VerifyOTP are deferred to a subsequent milestone pending regulatory TRAI DLT entity and header approvals.

</domain>

<decisions>
## Implementation Decisions

### 1. Channel Scope & Phasing
- **D-01: WhatsApp-Only Scope for Phase 05.1:** — **Reversibility:** costly — defines active provider methods.
  - Due to pending TRAI DLT entity and header registration, Phase 05.1 focuses 100% on WhatsApp (outbound templates, 2-way bot, delivery reports). SMS Flow API and SendOTP/VerifyOTP modules are pre-architected but deferred from production routing until DLT approvals clear.

### 2. Multi-Tenancy & Sender ID Strategy
- **D-02: Centralized Platform WABA Architecture:** — **Reversibility:** costly — tenant messaging configuration.
  - All clinics send WhatsApp messages via ClinicQ's verified business number. The message header and body dynamically inject `{{clinic_name}}` and `{{doctor_name}}` ensuring clear clinic branding with zero onboarding paperwork friction for individual clinics.

### 3. Document Delivery & WhatsApp Action Buttons
- **D-03: Secure Tokenized Document Delivery (`/r/[token]`):** — **Reversibility:** reversible — URL schema.
  - All shared clinical documents (prescriptions, lab reports, receipts, referrals) deliver as secure tokenized links (`https://clinicq.health/r/[token]`) via WhatsApp URL action buttons. Avoids costly WhatsApp media upload fees, bandwidth delays, and attachment size limits.
- **D-04: Interactive Quick Reply Buttons & Immediate Slot Release:** — **Reversibility:** costly — appointment lifecycle.
  - Outgoing appointment messages feature interactive buttons: `[Confirm]`, `[Cancel]`, `[Reschedule]`.
  - When patient clicks `[Cancel]`, the appointment is immediately marked `cancelled` (`cancellation_reason: 'patient_whatsapp_bot'`), freeing the doctor's calendar slot, auditing the event, triggering a waitlist alert to the front desk, and replying with a cancellation acknowledgement.
  - When patient clicks `[Reschedule]`, a 24-hour tokenized reschedule link (`/reschedule/[token]`) is sent to the patient.

### 4. Conversational Handling & Inbound Triage
- **D-05: Auto-Triage & Front-Desk In-App Notification:** — **Reversibility:** reversible — webhook handling.
  - Unhandled conversational replies or clinical inquiries from patients trigger an automated polite reply: *"Thank you for contacting us. We have received your message and our reception desk will assist you shortly. For urgent care, please call the clinic directly."*
  - Simultaneously creates an in-app alert (Event #18 `inbound_whatsapp_reply`) in the front-desk bell/drawer containing the exact patient text for staff follow-up.

### 5. Delivery Reports (DLR) Webhook
- **D-06: Outbox & Audit Delivery Tracking:** — **Reversibility:** reversible — webhook status handling.
  - Inbound status webhooks from MSG91 update `communication_queue` status to `delivered` or `read` with timestamps stored in `metadata`. Permanent failures (e.g. invalid number) set status to `failed` and alert the front desk if an urgent appointment notification failed.

### 6. Template Management & Tooling
- **D-07: Repository Template Catalogue & Sync Tooling:** — **Reversibility:** reversible — CLI tool.
  - Templates reside in `lib/messaging/templates/whatsapp-templates.json`.
  - Synchronizer script `scripts/msg91-sync-templates.ts` (`npm run msg91:sync-templates`) submits templates to MSG91 and supports `--status` flag to check Meta approval status.
  - `docstar-cli` initialized with all 14 MSG91 modules (`npx docstar-cli msg91 <module> <endpoint>`) for ad-hoc inspection and debugging.

### 7. Local Development & Failover
- **D-08: DevLogger Fallback for Development:** — **Reversibility:** reversible — provider factory.
  - When `MSG91_AUTH_KEY` is not configured or in local/test environments, the system seamlessly falls back to `DevLoggerProvider` which logs formatted messages to the console and `.planning/dev-messages.txt` with interactive simulation links.

### the agent's Discretion
- Parameter sanitization helper to strip invalid characters, line breaks, and enforce Meta variable length limits.
- Exact signature verification helper for MSG91 webhooks (header `authkey` or custom webhook secret).
- Structure of the unit and integration tests verifying MSG91 payload generation and webhook parsing.

</decisions>

<specifics>
## Specific Ideas

- **Positional Variable Formatting:** In MSG91 `template-bulk` API, parameters for template components are passed as objects under `components`:
  ```json
  "components": {
    "body_1": { "type": "text", "value": "Rahul Sharma" },
    "body_2": { "type": "text", "value": "Dr. Aditi Rao" }
  }
  ```
  The provider must map template parameter keys (e.g. `patient_name`, `doctor_name`) to the expected positional indices based on the template definition in `whatsapp-templates.json`.
- **CLI & MCP Tooling:** `docstar-cli msg91` is initialized with all modules and can be used to query numbers (`docstar-cli msg91 whatsapp to-fetch-whatsapp-number`) or check balance (`docstar-cli msg91 whatsapp check-whatsapp-prepaid-balance`).

</specifics>
