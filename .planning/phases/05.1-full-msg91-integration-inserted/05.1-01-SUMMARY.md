## 1. Executive Summary

Wave 1 of Phase 05.1 upgraded ClinicOS's messaging infrastructure from stubbed abstractions to an OpenAPI-compliant, production-grade outbound WhatsApp communications gateway powered by **MSG91**.

All 4 planned tasks were executed test-first and committed atomically:
1. **Wave 0 Test Suite (`tests/messaging/msg91-provider.spec.ts`):** 26 test cases covering positional mapping for all 13 templates, real caller parameter aliases from `features/*/actions.ts`, parameter sanitization (whitespace, newlines, Meta length limits), CTA URL button token extraction (`/r/[token]`), sender ID resolution, `template-bulk` payload structure, and active session text endpoint fallback.
2. **Database Migration `000016_comm_queue_delivery_status.sql` & TypeScript Types:** Expanded PostgreSQL `communication_queue_status_check` constraint to support `'delivered'` and `'read'` statuses, created a dedicated index on `communication_queue(external_message_id)` for high-performance DLR webhooks (Peer Review Finding 6), and updated `CommunicationStatus` in `lib/db/types.ts`.
3. **Template Positional Mapping Matrix & Sanitizer (`lib/messaging/templates/mapping.ts`):** Implemented strict positional variable mapping (`body_1`, `body_2`, ..., `button_1`) for all 13 pre-approved templates in `whatsapp-templates.json`, caller parameter alias resolution (`new_date_time`, `document_title`, `specialist_name`, `reason`, `prescription_url`, `receipt_url`), Meta sanitization (stripping newlines, collapsing spaces, length truncation), deterministic non-empty fallbacks (`"Patient"`, `"Doctor"`, `"Clinic"`, `"0"`), and CTA URL button token extraction (`https://app.thecliniqai.com/r/[token]` -> `[token]`).
4. **Production `Msg91Provider` (`lib/messaging/providers/msg91.ts`):** Conformed strictly to MSG91's `template-bulk` OpenAPI specification (`POST https://control.msg91.com/api/v5/whatsapp/whatsapp-outbound-message/bulk/`) using `to_and_components` and deterministic language policy (`policy: "deterministic"`). Added fallback routing to MSG91 active session text endpoint (`https://control.msg91.com/api/v5/whatsapp/whatsapp-outbound-message/`) for conversational / non-catalogue bot responses. Implemented dynamic sender ID resolution (`options.integratedNumber || options.senderId || process.env.MSG91_INTEGRATED_NUMBER || process.env.MSG91_SENDER_ID`). Preserved DevLogger fallback (Decision D-08) in `lib/messaging/index.ts`, ensured default clinic name in `dispatcher.ts`, and updated `.env.example`.

## 4. Key Design Decisions & Deviations

1. **Dual Export Naming:** Exported both `mapTemplateParameters` / `buildPositionalComponents`, `sanitizeParameter` / `sanitizeTemplateParameter`, and `extractDocumentToken` / `extractUrlToken` from `lib/messaging/templates/mapping.ts` to ensure compatibility across caller styles and test suites.
2. **Consultation Documents Button Resolution:** Resolved token extraction from `prescription_url` first (with fallback to `receipt_url` and bare `token`) for the `consultation_documents` template, allowing callers passing dual URLs to properly populate the single `/r/{{1}}` CTA URL button without defaulting to `"-"`.
3. **DevLogger Fallback Behavior (Decision D-08):** In `lib/messaging/index.ts`, when `MESSAGING_PROVIDER=msg91` is configured in environment without `MSG91_AUTH_KEY`, `getMessagingProvider()` seamlessly falls back to `DevLoggerProvider` in local/test runs unless explicitly overridden with `getMessagingProvider("msg91")`.
