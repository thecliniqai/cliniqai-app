<objective>
Implement Wave 1 of Phase 05.2:
1. Create centralized Indian phone utility library (`lib/utils/phone.ts`) adhering to the Indian National Numbering Plan (NNP) (`/^[6-9]\d{9}$/`), supporting subscriber digit extraction (`extractTenDigits`), E.164 transformation (`toE164`), format validation (`isValidIndianMobile`), and standard 5+5 display formatting (`formatTenDigitsDisplay`).
2. Establish Wave 0 unit test suite in `tests/utils/phone.spec.ts` covering valid mobile formats, invalid landline prefixes, non-numeric strings, edge cases, and transformations.
3. Write idempotent database migration `supabase/migrations/000017_normalize_indian_phone_numbers.sql` standardizing existing telephone records in `patients`, `staff_members`, `clinics`, and `communication_queue` to `+91XXXXXXXXXX` format.
4. Upgrade application Zod boundary schemas (`features/patients/schema.ts`, `features/settings/schema.ts`) and duplicate patient detection (`features/patients/dedup.ts`) to strictly enforce 10-digit Indian numbers and E.164 persistence.
</objective>

  <action>
    1. Create `lib/utils/phone.ts` exporting:
       - `INDIAN_MOBILE_REGEX = /^[6-9]\d{9}$/`: Strict regular expression for valid Indian mobile numbers.
       - `extractTenDigits(phone: string | null | undefined): string`:
         - Strips all non-digit characters (`replace(/\D/g, "")`).
         - If 10 digits, returns as-is.
         - If 11 digits starting with "0", strips leading "0".
         - If 12 digits starting with "91", strips leading "91".
         - If more than 10 digits, slices the last 10 digits (`digits.slice(-10)`).
         - Returns empty string for null, undefined, or empty values.
       - `toE164(phone: string | null | undefined): string`:
         - Extracts 10 digits via `extractTenDigits`.
         - If 10 digits and satisfies `INDIAN_MOBILE_REGEX`, returns `+91${digits}`.
         - Otherwise returns trimmed original string or empty string.
       - `isValidIndianMobile(phone: string | null | undefined): boolean`:
         - Returns `true` if `extractTenDigits` yields exactly 10 digits matching `INDIAN_MOBILE_REGEX`, `false` otherwise.
       - `formatTenDigitsDisplay(phone: string | null | undefined): string`:
         - Extracts 10 digits and groups as 5+5 (`${digits.slice(0, 5)} ${digits.slice(5, 10)}`).
         - Returns partial digits if length <= 5.
    2. Create `tests/utils/phone.spec.ts` testing:
       - `extractTenDigits`:
         - Formatted strings (`"+919876543210"`, `"919876543210"`, `"09876543210"`, `"98765-43210"`, `"+91 98765 43210"`).
         - Partial strings (`"98765"`).
         - Null, undefined, empty string handling.
       - `isValidIndianMobile`:
         - Accepts valid numbers starting with 6, 7, 8, or 9 (`"9876543210"`, `"8888888888"`, `"7777777777"`, `"6666666666"`).
         - Rejects invalid prefixes starting with 0-5 (`"0123456789"`, `"5555555555"`, `"1234567890"`).
         - Rejects strings with fewer or more than 10 digits.
       - `toE164`:
         - Converts valid numbers to `+91XXXXXXXXXX`.
         - Handles inputs with existing `+91`, `91`, leading `0`, spaces, and dashes.
       - `formatTenDigitsDisplay`:
         - Formats 10-digit number to `"98765 43210"`.
  </action>
