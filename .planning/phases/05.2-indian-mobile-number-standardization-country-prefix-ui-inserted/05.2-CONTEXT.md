<domain>
## Phase Boundary

Standardize and reinforce Indian mobile phone number handling across the entire ClinicOS application.
This phase delivers:
1. A reusable, accessible `PhoneInput` component (`components/ui/phone-input.tsx`) featuring an inset Indian flag (`🇮🇳`), fixed `+91` badge with subtle divider, real-time numeric filtering (`maxLength={10}`), and clean error styling conforming to `DESIGN.md`.
2. Strict 10-digit Indian mobile validation (`/^[6-9]\d{9}$/`) across frontend forms and backend Zod schemas.
3. Industry-standard ITU-T E.164 database persistence (`+919876543210`), ensuring seamless delivery with WhatsApp (MSG91) and SMS gateways (which normalize to `919876543210`).
4. Upgrade of all 8 mobile number input locations across the application.
5. Flexible search compatibility allowing users to search by partial or full 10-digit numbers without typing `+91`.
6. An idempotent SQL database migration (`000017_normalize_indian_phone_numbers.sql`) cleaning and standardizing existing phone records in the database.

</domain>

<decisions>
## Implementation Decisions

### Persistence & Storage Standards
- **D-01:** **E.164 Database Persistence:** Mobile numbers in PostgreSQL (`patients.phone`, `staff_members.phone`, `clinics.phone`, `communication_queue.recipient_phone`) are strictly stored in standard international E.164 format with leading `+91` prefix (e.g. `+919876543210`).
  - *Rationale:* Worldwide telecommunications and healthcare standard (ITU-T E.164). Supported natively by Supabase Auth, Twilio, Meta WhatsApp Cloud API, and MSG91 (where `to.replace(/[^0-9]/g, "")` cleanly produces `919876543210`).
  - *Reversibility:* costly — database migration and multiple model/action call sites.

### Validation & Input Rules
- **D-02:** **Strict Indian Mobile Validation:** Every phone number entered into the system must strictly consist of exactly 10 digits starting with 6, 7, 8, or 9 (`/^[6-9]\d{9}$/`). Numbers with fewer or more digits, or starting with 0–5, are rejected with clear user error messaging: "Please enter a valid 10-digit Indian mobile number starting with 6-9."
  - *Reversibility:* reversible — regex constraint in shared schemas.
- **D-03:** **Real-Time Input Filtering:** As the user types or pastes into the mobile number input, the component automatically strips all non-numeric characters (`e.target.value.replace(/\D/g, "")`) and caps the input length at 10 digits (`.slice(0, 10)`). Pasting with `+91`, `91`, or leading `0` automatically strips the prefix and retains the 10-digit subscriber number.
  - *Reversibility:* reversible — component event handler.

### UI & Component Architecture
- **D-04:** **Reusable `PhoneInput` Component:** Create `components/ui/phone-input.tsx` conforming to `DESIGN.md` light-only design system.
  - Visual structure: Unified input box with subtle border (`border-gray-300 focus-within:ring-2 focus-within:ring-[#1769E0] focus-within:border-[#1769E0]`), left-hand fixed inset containing the Indian Flag (`🇮🇳`) and `+91` prefix with a vertical border divider (`border-r border-gray-200 pr-2 mr-2`), and a seamless `<input type="tel" inputMode="numeric" placeholder="98765 43210" maxLength={10} />`.
  - Prop contract: Accepts `value` (can be bare 10-digit or full E.164 `+91...`), strips `+91` internally so user only sees and edits 10 digits, and emits normalized values via `onChange(value, e164Value)`.
  - *Reversibility:* reversible — isolated UI component.
- **D-05:** **Application-Wide Text Box Upgrades:** Replace raw `<input type="tel">` and text fields with `PhoneInput` across all 8 identified entry points:
  1. Patient Registration (`app/(dashboard)/patients/new/page.tsx`)
  2. Edit Patient Modal (`components/patients/edit-patient-modal.tsx`)
  3. Appointment Booking Drawer (`components/calendar/booking-drawer.tsx`)
  4. Waitlist Drawer (`components/calendar/waitlist-drawer.tsx`)
  5. Queue Walk-in Drawer (`components/queue/walk-in-drawer.tsx`)
  6. Staff Invitation & Edit Modal (`components/staff/edit-staff-modal.tsx`, `app/(dashboard)/staff/page.tsx`)
  7. Clinic Profile Form (`components/settings/clinic-profile-form.tsx`)
  8. User Profile Form (`components/profile/user-profile-form.tsx`)
  - *Reversibility:* costly — touches 8 distinct UI forms.

### Search Compatibility & Data Migration
- **D-06:** **Flexible Phone Search:** Search inputs (Global Search modal `components/layout/global-search-modal.tsx`, Patient Directory `components/patients/patient-directory-table.tsx`, Visits Register `components/visits/visits-register-view.tsx`) must allow users to search by typing 10 digits or partial phone numbers without needing to type `+91`. Queries normalize input digits to match against stored E.164 phone numbers (e.g. searching `98765` or `9876543210` matches `+919876543210`).
  - *Reversibility:* reversible — query normalization utility.
- **D-07:** **Existing Data Normalization Migration:** Provide an idempotent SQL migration `supabase/migrations/000017_normalize_indian_phone_numbers.sql` that cleans existing rows in `patients`, `staff_members`, `clinics`, and `communication_queue`:
  - Strips non-digits, strips leading `0` or `91` if 12 digits, and prepends `+91` to ensure every valid 10-digit number is stored as `+91XXXXXXXXXX`.
  - *Reversibility:* one-way — database data modification migration.

### the agent's Discretion
- Exact styling details of the `PhoneInput` component (padding, font size, icon dimensions) following `DESIGN.md`.
- Shared helper function location (`lib/utils/phone.ts` or `lib/formatters/phone.ts`) for formatting, stripping prefixes, and validating Indian numbers.

</decisions>

<specifics>
## Specific Ideas

- **Visual Appearance:**
  ```text
  ┌─────────────────────────────────────────────────────────────┐
  │ [🇮🇳 +91] │  98765 43210                                     │
  └─────────────────────────────────────────────────────────────┘
  ```
  The badge `🇮🇳 +91` is fixed, non-editable, and visually distinct inside the left edge of the input box.
- **Copy-Paste Tolerance:** If a user copies an Indian phone number from WhatsApp or Truecaller (e.g. `+91 98765-43210` or `09876543210`), pasting it into the input automatically cleans it down to the 10 digits `9876543210`.
