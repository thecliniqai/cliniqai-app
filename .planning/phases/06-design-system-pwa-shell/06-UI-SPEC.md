**Precedence rule (CTO default CD-01).** Where DESIGN_SYSTEM.md (written 2026-11-10, IBM Plex and teal) differs from
the G2-D-approved files, the approved files win: palette, fonts, type scale (14 px desktop body), control sizes
(36/32/28 px desktop, 44 px touch), radii 6/10/14/20, 20 px status pills, top bar 52 / sidebar 216 / rail 56 / bottom
bar 60, and the 11 px uppercase eyebrow. DESIGN_SYSTEM.md still governs behaviour, semantics, content formats and
accessibility conventions (§5, §6 behaviour, §7 patterns, §8). The doc errata are proposed at phase close (06-PLAN
"Open for the PO" item 6), not here.

**PO preferences this contract encodes** (memory, G2-D): premium, white-first canvas; information-dense but never
cramped; compact chips; tap-first with near-zero typing for doctors (complaints, examination templates with quick
tiles, diagnosis and the prescription builder are tap flows); everything tokenised so it can change later.

**Tokenisation rule.** Components use only the semantic (layer 2), structure (layer 3) and component (layer 4) tokens
named below, through Tailwind utilities (`bg-surface`, `text-fg-muted`, `border-border-control`, `h-control-dense`,
`rounded-md`, `shadow-popover` …) or `var(--…)`. No raw palette names (`mineral-*`, `primary-*`, `teal-*`, `brass-*`),
no hex, no `text-[Npx]`, no Tailwind default palette in new code. The only literal colours allowed in a component file
are the brand-mark gradient stops in `components/brand/brand-mark.tsx` (06-01b).

### Focus treatment

```css
:focus-visible {
  outline: var(--focus-ring-width) solid var(--color-ring);   /* 2px #3A80D9 */
  outline-offset: var(--focus-ring-offset);                    /* 2px */
  box-shadow: 0 0 0 var(--focus-ring-offset) var(--color-ring-halo); /* 2px white halo */
}
```

- The ring always sits **outside** the control on the 2 px white halo: `ring` on `ring-halo` 3.99:1 (binding), on
  canvas/surface 3.99:1, on `surface-soft` 3.78:1, on `sunken`/`surface-muted` 3.61:1, on `selected` 3.63:1. `ring`
  on `accent` is **1.29:1**, so the ring is never drawn inside or directly on a blue control or fill.
- Every primitive applies the treatment itself (06-02a revision); never `outline: none` without this replacement.
- **Inset variant (CD-12):** full-bleed rows inside a clipping or scrolling container (queue rows in a lane, DataList
  rows, listbox options, palette rows, menu items) use `outline-offset: -2px` and no halo, so the ring is not clipped;
  the inset variant is never used on an accent-filled element. Scroll containers that hold outset-ring controls keep
  ≥ 4 px inner padding.
- Focus is never hidden by sticky bars (WCAG 2.4.11): `scroll-padding-top: calc(var(--spacing-bar) + 8px)`,
  `scroll-padding-bottom: calc(var(--spacing-bottom-bar) + 8px)` on `html`.
- Test (06-02a `keyboard/forms.spec.ts`): computed outline ≥ 2 px in the `ring` colour with a positive offset on every
  primitive in `/dev/ui`.
