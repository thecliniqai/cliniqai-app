## Deviations

1. **The page's deployment id is not read from `data-dpl-id` on the live page** (plan step 4 says
   `document.documentElement.dataset.dplId`). Next writes the attribute into the server HTML, then its client runtime
   reads it, removes it before hydration and keeps it as `globalThis.NEXT_DEPLOYMENT_ID`
   (`next/dist/shared/lib/deployment-id.js`). The first e2e run showed no update ever detected (`e2e-first-targeted-run.txt`).
   `currentPageDeploymentId()` reads the global first and the attribute as a fallback; the e2e asserts the attribute in
   the server HTML and the global on the page (Rule 1).
2. **`generateBuildId → null` in `next.config.ts`** (not in the plan). With a `deploymentId`, Next writes one constant
   BUILD_ID (`build-TfctsWXpff2fKS`) for every build, which silently weakened the e2e lane's stale-build guard (RL-16:
   `.next/BUILD_ID` vs the stamp). Rule 2; `env-boot.spec.ts` pins it.
3. **The service-worker build stamp stays separate from the deployment id** (06-09a's wave note allowed reuse). On
   Vercel both are `VERCEL_DEPLOYMENT_ID`; the e2e lane's fixed `NEXT_DEPLOYMENT_ID` would otherwise give two builds the
   same worker stamp and break `e2e:sw-update`.
4. **Lock e2e uses a real subscription expiry, not a mocked `redirect`.** A mocked `/billing/locked` for a `full` clinic
   is bounced back to `/` by the destination page (05-10b `requireAccessDestination`), and the next check would mock it
   again: a loop, not "the real locked page". The spec seeds a fresh clinic, signs its owner in, expires the
   subscription with the 05-10b helper and resumes: the real status answer sends the page to the real `/billing/locked`
   with the cookie kept. (V2-13b's spec 9 still owns the billing-driven transition.)
5. **Removed member → 401, not 403.** `remove_member` deletes the member's sessions (05-05), so the poll's `getUser()`
   fails first and the client runs `hardSignOut("expired")`; the browser outcome (purge, `/login`) is the plan's. The
   403 → `"removed"` path (a removed membership with a live session) is proven in `session-status-db` and the unit specs.
6. **Answers beyond the plan's three statuses**: 409 `clinic_selection_required` (several clinics, none chosen: never a
   sign-out) and 503 `unavailable` (a lookup error: the client does nothing; the database is the control). A cookie that
   names a clinic the user left answers 403 (`no_membership`).
7. **A dirty form also blocks the navigation that removes it** (conservative reading of "no form with unsaved input":
   the user typed, then navigated; the reload waits one more navigation). Spec 6's "with text typed into a form field, a
   client navigation does not reload" is that case.
8. **Skew in e2e uses the patient edit modal** (its `onSubmit` awaits the action without a catch, so an unknown action
   reaches `unhandledrejection`); forms that run actions inside `startTransition` surface the same error through the route
   boundary, which already shows 06-04a's skew copy and now also calls the skew guard. It submits with Enter: on
   Pixel 7 the v1 modal overflows and its footer never settles for a click (v1 layout, not 06-06).
9. **The card's "never on the checkout drawer"** is asserted on `/queue` (the drawer's page): opening the drawer needs a
   queue entry in checkout state; the card is rendered only by Today's page component, so no other tree can hold it.
10. **Install UI checks run on Chromium with an iPhone UA** (the iOS path renders there); the WebKit proof is
    `10-ipados.spec.ts`. Chromium's `beforeinstallprompt` (the Android prompt path) is not driven in e2e: Playwright
    cannot make Chrome fire it deterministically; `installMode`'s prompt branch is unit-tested.
11. **Existing specs adjusted**: exact `localStorage`/`sessionStorage` key assertions in `05-cache-audit`,
    `user-menu-keyboard` and `06-tabs-and-devices` now allow `clinicos.pref.signedInSessions` (a D-3 preference the
    purge keeps by design; the same name in `sessionStorage` is the per-session "counted" marker, so no new key exists).
12. **`ci.yml` comments and `package.json` `e2e:pr`** gained `pwa-ipados` (plan: project in `playwright.config.ts`; the
    PR lane must run it to keep spec 10 enforced). No dependency added.
13. **Tracer commit order**: `4267ed4` reads `deploymentInfo().deploymentId`, added by the next commit `9bf07c3`.
14. **AccessPageShell and `/billing/locked`** moved from v1 palette classes to semantic tokens while their sign-out was
    rewired (06-01a rule); `locked.spec`'s axe cases pass at 360/820/1280.

## Threats

- **T (forged tenant):** the route reads no input; `?tenant=` ignored (guard leg, db spec, mutant).
- **T (open redirect through the status answer):** only the three 05-10b destinations are ever followed
  (`parseSessionStatus`; mutant).
- **T (sign-out on a blip / denial of service):** 5xx, 409, timeouts and network errors never sign out (unit, mutant);
  only a same-origin 401/403 does.
- **T (stale code over typed input):** never an automatic reload over unsaved input, a running command or after a skew
  notice (unit, e2e, mutants).
- **T (PHI on screen during a lock):** `onLocked` conceals before the cleanups; the database stop (05-10a) stays the
  control.
- **T (`intent://` link carrying a token):** built from host and path only (unit, mutant).
- New surface: `GET /api/session-status` (authenticated, `no-store`, no PHI; guard kind `session-status`). Adversarial
  review B (plan) is the orchestrator's next step.
