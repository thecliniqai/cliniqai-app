## Root causes (each needs the slow runner to show; fast runners win the races)

**A. Two `<main>` landmarks on the consult.** `components/consultation/consultation-workspace.tsx` (v1, 03-02) wrapped
its sections in a second `<main>` inside the shell's `<main id="main">`. It streams in about 250 ms after `page.goto`
(`main-probe.txt`: role=main count 1 at +20 ms, 2 from +280 ms). Specs that assert `getByRole("main")` right after
`goto` on the consult (M1, M4 signed in, ui-checks, 08-layout desktop) pass when the assertion runs first and hit a
strict-mode violation when the workspace is already there. The local full lane reproduced it once (08-layout desktop:
"getByRole('main') resolved to 2 elements"), and the 43688840332 artifact shows the same error on ui-checks and
08-layout. It is also an accessibility defect (axe `landmark-no-duplicate-main`, moderate, below the blocking gate).
Throttling only the browser (x6) did not force the race (`consult-main-restored-cpu6-not-reproduced.txt`): on CI the
server is slow too. The landmark test below is deterministic either way: it waits for the workspace, then counts.

**B. Times rendered in the runtime's zone (P1-21 stragglers).** `components/calendar/doctor-timeline.tsx` placed visits
with `Date#getHours()`; the patient record formatted dates without `timeZone`. With the server in one zone and the
browser in another the two renders differ and React throws the server HTML away (error #418) and renders again. The m0
specs run the browser in Asia/Kolkata against CI's UTC server; on a slow runner the "+ Book Appointment" or "Cancel
Appointment" click lands during that window and is lost (43688840332 artifact: drawer never opened, confirm() never
shown, trace `pageerror` "Minified React error #418"). `hydration-*.txt`: UTC/UTC and IST/IST clean; UTC server + IST
browser gives #418 on `/calendar` (with a visit) and on `/patients/<id>`. Production has the same pairing (UTC
servers, Indian browsers). The booking drawer also turned the picked date and time into an instant in the browser's
zone while the timeline and the server read the clinic's. Reproduced locally with CI's conditions (server `TZ=UTC`,
browser CPU throttled x6 through a temporary fixture change, both reverted): with the calendar fix reverted the m0
specs fail exactly as on CI (book a free slot passes; overbook "Schedule Appointment" not found, F-04 "Expected to
fail, but passed", cancel card stays; 6.0-6.2 s each), and with it they pass
(`m0-server-utc-cpu6-calendar-fix-reverted.txt`, `m0-server-utc-cpu6-fixed.txt`). After the fix the zone probe is
clean everywhere for a UTC server and an IST browser (`hydration-server-utc-browser-ist-after-fix.txt`).

**C. overlays-axe budget.** Ten whole-page axe scans of `/dev/ui` plus ten captures: 18-19 s locally, 28.8-29.6 s on a
normal CI runner, over the 30 s default on a slower one. CPU throttling x4 reproduces "Test timeout of 30000ms
exceeded" at every width (`overlays-throttle-red4.txt`).

## CI budget (no retry-policy change)

Retries stay as TEST_STRATEGY §8 sets them (2 on CI, reported, never a pass). The e2e job limit goes from 30 to 45
minutes and the PR lane runs with `--global-timeout=2400000` (40 min): a green lane takes about 20 minutes on a normal
runner and about 30 on a 1.5x one, which left no room, and a job cancelled at its limit runs no `!cancelled()` step, so
the summary and the artifact were lost. With the lane's own limit the run ends with its report and traces uploaded
(checked locally: `--global-timeout` still writes `playwright-report/results.json` and the summary script reads it).
The global timeout also cuts the global teardown (run data and paused cron stay); on CI the stack is discarded, and
the local `npm run e2e:pr` sets no global timeout.
