<objective>
Build the core data models, server actions, and name resolution logic for doctor availability, split shifts, time-off blocking, and doctor slot durations:
1. Create database migration `000012_doctor_availability_and_blocks.sql` adding `availability_schedule` (JSONB) and `default_slot_duration_minutes` (INTEGER) to `memberships`, plus the `schedule_blocks` table with multi-tenant RLS.
2. Update TypeScript database types in `lib/db/types.ts`.
3. Create centralized `getTenantDoctorDirectory()` and `getTenantStaffDirectory()` in `features/staff/actions.ts` that properly resolves names (fixing the raw `Dr. (780d382b)` UUID bug across Calendar, Cabin, and Queue).
4. Update `app/(dashboard)/calendar/page.tsx`, `app/(dashboard)/queue/page.tsx`, `app/(dashboard)/cabin/page.tsx`, and `features/queue/actions.ts` to use clean resolved doctor names.
5. Enhance `features/visits/scheduling.ts` with `checkSlotAvailability` that inspects doctor shift hours and schedule blocks.
6. Write unit tests in `tests/scheduling/availability-blocks.spec.ts`.
</objective>

<threat_model>
| Threat ID | Category | Component | Description | Severity | Mitigation |
|-----------|----------|-----------|-------------|----------|------------|
| T-03.3-01 | Broken Access Control / Cross-Tenant Leak | `schedule_blocks` table | A user from Tenant A queries or inserts blocked time in Tenant B. | high | Enforce `tenant_id = current_user_tenant_ids()` in Supabase RLS and `getActiveMembership()` in server actions. |
| T-03.3-02 | Privilege Escalation | Schedule Block Creation | Non-admin/non-doctor staff blocking all clinic doctors arbitrarily. | medium | Enforce role check: doctors can only block their own time; admins/owners can block any doctor or clinic-wide. |
</threat_model>

<tasks>
1. **Database Migration `supabase/migrations/000012_doctor_availability_and_blocks.sql`**:
   - `ALTER TABLE public.memberships ADD COLUMN IF NOT EXISTS availability_schedule JSONB DEFAULT '{"monday":{"enabled":true,"shifts":[{"start":"10:00","end":"13:00"},{"start":"17:00","end":"21:00"}]},"tuesday":{"enabled":true,"shifts":[{"start":"10:00","end":"13:00"},{"start":"17:00","end":"21:00"}]},"wednesday":{"enabled":true,"shifts":[{"start":"10:00","end":"13:00"},{"start":"17:00","end":"21:00"}]},"thursday":{"enabled":true,"shifts":[{"start":"10:00","end":"13:00"},{"start":"17:00","end":"21:00"}]},"friday":{"enabled":true,"shifts":[{"start":"10:00","end":"13:00"},{"start":"17:00","end":"21:00"}]},"saturday":{"enabled":true,"shifts":[{"start":"10:00","end":"13:00"},{"start":"17:00","end":"21:00"}]},"sunday":{"enabled":false,"shifts":[]}}'::jsonb;`
   - `ALTER TABLE public.memberships ADD COLUMN IF NOT EXISTS default_slot_duration_minutes INTEGER DEFAULT 15;`
   - `CREATE TABLE IF NOT EXISTS public.schedule_blocks (id UUID PRIMARY KEY DEFAULT gen_random_uuid(), tenant_id UUID NOT NULL REFERENCES public.tenants(id) ON DELETE CASCADE, doctor_id UUID REFERENCES auth.users(id) ON DELETE CASCADE, start_time TIMESTAMPTZ NOT NULL, end_time TIMESTAMPTZ NOT NULL, reason TEXT, all_day BOOLEAN DEFAULT false, created_by UUID NOT NULL REFERENCES auth.users(id), created_at TIMESTAMPTZ NOT NULL DEFAULT now());`
   - Add RLS policies for `schedule_blocks` (SELECT, INSERT, UPDATE, DELETE) scoped to `tenant_id IN (SELECT public.current_user_tenant_ids())`.

2. **Database Types in `lib/db/types.ts`**:
   - Define `DayShiftSchedule = { start: string; end: string }`
   - Define `DayAvailability = { enabled: boolean; shifts: DayShiftSchedule[] }`
   - Define `DoctorWeeklySchedule = Record<"monday"|"tuesday"|"wednesday"|"thursday"|"friday"|"saturday"|"sunday", DayAvailability>`
   - Update `Membership` interface with `availability_schedule?: DoctorWeeklySchedule | null` and `default_slot_duration_minutes?: number`.
   - Define `ScheduleBlock` interface.

3. **Centralized Doctor Directory in `features/staff/actions.ts`**:
   - Export `getTenantDoctorDirectory()`:
     - Derives session via `getActiveMembership()`.
     - Queries `memberships` table for doctors and practicing owners.
     - Formats clean display names: `Dr. ${m.full_name}` if not already prefixed, with graceful fallback to `Doctor (${index + 1})` or email prefix if full_name is missing, NEVER raw sliced UUID `(780d382b)`.
     - Returns `id` (user_id), `name`, `full_name`, `role`, `specialty`, `default_slot_duration_minutes`, `availability_schedule`.
   - Update `app/(dashboard)/calendar/page.tsx`, `app/(dashboard)/queue/page.tsx`, `app/(dashboard)/cabin/page.tsx`, and `features/queue/actions.ts` to call this directory and use clean doctor names.

4. **Availability & Schedule Block Actions in `features/visits/scheduling.ts` & `features/settings/actions.ts`**:
   - Implement `createScheduleBlock({ doctor_id, start_time, end_time, reason, all_day })` with authorization.
   - Implement `deleteScheduleBlock(blockId: string)`.
   - Implement `getScheduleBlocksForDate(dateStr: string, doctorId?: string)`.
   - Enhance `checkSlotAvailability`:
     - Checks visit overlap.
     - Checks if requested time is within the doctor's active day shifts (`availability_schedule`).
     - Checks if requested time overlaps with any `schedule_blocks`.
     - Returns `{ available: boolean, isOffDuty?: boolean, isBlocked?: boolean, blockReason?: string, conflictingVisit?: Visit }`.

5. **Unit Tests in `tests/scheduling/availability-blocks.spec.ts`**:
   - Test shift evaluation logic: correctly allows 10:30 AM (morning shift), flags 3:00 PM (break between shifts), allows 6:00 PM (evening shift), flags Sunday (closed).
   - Test `schedule_blocks` collision detection across specific time spans, full-day blocks, and multi-day ranges.
   - Test doctor name resolution fallback logic ensuring no raw sliced UUIDs are output.
</tasks>
