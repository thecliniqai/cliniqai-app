<objective>
Build the user interfaces for managing doctor weekly shifts, appointment slot durations, and time-off blocking:
1. Create `DoctorAvailabilityCard` in `components/profile/doctor-availability-card.tsx` supporting day toggles, split shifts (morning + evening), and default slot duration.
2. Integrate `DoctorAvailabilityCard` into `components/profile/user-profile-form.tsx` for self-management by doctors.
3. Update `components/staff/edit-staff-modal.tsx` so Clinic Admins and Owners can manage shift timings, slot durations, and blocks for any doctor on their behalf.
4. Build `BlockTimeModal` (`components/calendar/block-time-modal.tsx`) for blocking time windows, full days, or date ranges with reasons.
5. Update `features/settings/actions.ts` with `updateDoctorAvailability` and `updateDoctorSlotDuration`.
6. Add component tests in `tests/components/doctor-availability.spec.ts`.
</objective>

<threat_model>
| Threat ID | Category | Component | Description | Severity | Mitigation |
|-----------|----------|-----------|-------------|----------|------------|
| T-03.3-03 | Authorization Bypass | `updateDoctorAvailability` | A non-admin user updating another doctor's availability schedule. | high | Check in server action: if `user_id !== auth.uid()`, require caller to have `role IN ('owner', 'admin')` in the same tenant. |
| T-03.3-04 | Invalid Schedule Payload | `updateDoctorAvailability` | Malformed time strings or invalid intervals (e.g. end time before start time). | medium | Validate using Zod schema: `start < end`, valid HH:mm format, and no internal shift overlaps within the same day. |
</threat_model>

<tasks>
1. **Server Actions in `features/settings/actions.ts`**:
   - Implement `updateDoctorAvailability({ membership_id, availability_schedule })` with Zod validation.
   - Implement `updateDoctorSlotDuration({ membership_id, default_slot_duration_minutes })`.
   - Implement `getDoctorScheduleBlocks(doctorId: string)` and `deleteDoctorScheduleBlock(blockId: string)`.

2. **Weekly Shift & Duration Editor in `components/profile/doctor-availability-card.tsx`**:
   - Build accessible TailAdmin-styled card matching `DESIGN.md`.
   - Default Slot Duration dropdown: 15 mins (default), 20 mins, 30 mins, 45 mins, 60 mins.
   - Day-by-day weekly table:
     - Each day (Monday to Sunday) has an active switch toggle.
     - When active, shows Shift 1 (e.g. Morning: 10:00 to 13:00) and optional Shift 2 (e.g. Evening: 17:00 to 21:00).
     - Clean time pickers / dropdowns with 15-minute granularity.
     - Preset buttons: "Apply Monday to All Weekdays (Mon-Fri)", "Copy to Saturday".
   - Active Blocks section:
     - Displays upcoming blocked dates / times with reason tags.
     - "Block Time / Date" button opening `BlockTimeModal`.
     - Delete action for each block.

3. **Time-Off Blocker Modal in `components/calendar/block-time-modal.tsx`**:
   - Modal with clean tabs or radio options:
     - Single Time Interval (Date, Start Time, End Time)
     - Full Day (Date)
     - Date Range (Start Date, End Date)
   - Doctor selector (for Admins; defaults to current doctor for Doctors).
   - Reason input (e.g. "Surgery", "Leave", "Clinic Maintenance").
   - Instant save triggering optimistic update or router refresh.

4. **Staff Management Integration in `components/staff/edit-staff-modal.tsx`**:
   - When editing a doctor membership, add "Working Hours & Schedule" section:
     - Admin can view/edit the doctor's weekly split shifts and default slot duration.
     - Admin can add or remove blocked time on the doctor's behalf.

5. **Component Tests in `tests/components/doctor-availability.spec.ts`**:
   - Test shift validation: rejects shifts with end before start.
   - Test preset applications ("Apply to Weekdays").
   - Test permission guards (doctor vs admin permissions).
</tasks>
