# Plan 03.3-01 Summary: Doctor Availability Data Models, Server Actions, & Name Resolution

## Overview
Built the database schema, TypeScript types, server actions, and centralized name resolution for doctor weekly schedules (with split shifts), schedule time-off blocks, and appointment slot duration. Fixed the raw UUID doctor name issue across the Calendar, Queue, and Cabin pages.

## Deliverables
1. **Database Migration (`supabase/migrations/000012_doctor_availability_and_blocks.sql`)**:
   - Added `availability_schedule` (JSONB) with default morning (10:00–13:00) and evening (17:00–21:00) split shifts to `memberships`.
   - Added `default_slot_duration_minutes` (INTEGER default 15) to `memberships`.
   - Created `schedule_blocks` table with multi-tenant RLS for doctor-specific and clinic-wide leaves, vacations, and emergency closures.
2. **Database Types (`lib/db/types.ts`)**:
   - Added `DoctorWeeklySchedule`, `DayAvailability`, `DayShiftSchedule`, and `ScheduleBlock` interfaces.
   - Updated `Membership` and `Database['public']['Tables']` definitions.
3. **Doctor & Staff Directory with Clean Name Resolution (`features/staff/actions.ts`)**:
   - Created `getTenantDoctorDirectory()`, `getTenantStaffDirectory()`, and `getTenantDoctorMap()`.
   - Built `formatDoctorDisplayName()` formatting names as `Dr. <Name>`, falling back to `Doctor (<N>)` or email prefixes, never raw truncated UUIDs.
   - Updated `app/(dashboard)/calendar/page.tsx`, `app/(dashboard)/queue/page.tsx`, `app/(dashboard)/cabin/page.tsx`, and `features/queue/actions.ts` to use centralized directory resolution.
4. **Enhanced Slot Availability & Schedule Block Actions (`features/visits/scheduling.ts`)**:
   - Implemented `createScheduleBlock()`, `deleteScheduleBlock()`, `getScheduleBlocksForDate()`.
   - Enhanced `checkSlotAvailability()` to verify:
     - Doctor working shift hours (`isOffDuty: true` when outside active shifts or on break).
     - Active schedule blocks (`isBlocked: true` with reason when doctor or clinic is blocked).
     - Existing non-cancelled visits for double-booking prevention.
5. **Unit Tests (`tests/scheduling/availability-blocks.spec.ts`)**:
   - 17 unit tests covering shift range matching, ISO/IST conversions, fallback name resolution, and schedule block collision detection.
   - 100% tests passing.
