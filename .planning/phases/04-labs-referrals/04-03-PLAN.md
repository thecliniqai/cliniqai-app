<objective>
Build the end-to-end referrals lifecycle, branded PDF referral letter generator, centralized referrals register, and loop-closure workflow for Phase 4:
1. Implement the Referrals data layer in `features/referrals/` supporting both out-of-network specialists and in-network partner clinics with DPDP consent recording.
2. Build the `@react-pdf/renderer` branded Referral Letter generator (`features/referrals/pdf/`) supporting clinic letterhead, doctor credentials, patient summary, provisional diagnosis, active medications, and dual letterhead modes (`blank_paper` vs `preprinted_letterhead`).
3. Build the centralized clinic Referrals Register (`app/(dashboard)/referrals/page.tsx` and `components/referrals/referrals-register.tsx`) with Outbound and Inbound tabs, search, filters, and a 1-tap "Close the Loop" modal for returning patients.
4. Integrate referral entry points into both active Consultation Cabin (`components/consultation/consultation-workspace.tsx`) and the Patient Profile (`components/patients/patient-detail-view.tsx`), and display referral status on the visit timeline.
5. Add the "Referrals" item to `components/layout/app-sidebar.tsx`.
6. Verify the complete referrals test suite in `tests/referrals/referrals-flow.spec.ts`.
</objective>

<threat_model>
| Threat ID | STRIDE Category | Component | Description | Severity | Mitigation |
|-----------|-----------------|-----------|-------------|----------|------------|
| T-04-08 | Information Disclosure | In-Network History Sharing | Sharing patient clinical history with receiving clinic without explicit patient consent. | High | Enforce mandatory DPDP consent toggle before packaging clinical history; record consent event in `consent_records`; package immutable snapshot in `consented_history_snapshot`. |
| T-04-09 | Tampering / Privilege Escalation | Receiving Clinic Access | Receiving clinic attempting to edit originating diagnosis or clinical notes of a referral. | High | PostgreSQL RLS policy on `referrals` restricts receiving tenant to `UPDATE` only on acknowledgment and loop-closure fields (`status`, `acknowledged_at`, `completed_at`, `closure_notes`), preventing modification of clinical diagnoses. |
| T-04-10 | Repudiation | Referral Actions | Clinician disputing creating a referral or closing a referral loop. | Medium | Enforce structured audit logging via `recordAudit()` recording user ID, tenant ID, action (`referral.create`, `referral.close_loop`), and target referral ID. |
| T-04-11 | Information Disclosure / Cross-Tenant Leak | Referrals Register | Clinic A viewing outbound or inbound referrals belonging to Clinic B. | High | Query scoped strictly to `tenant_id = session.tenantId` for outbound and `target_tenant_id = session.tenantId` for inbound, enforced by both server actions and RLS policies. |
</threat_model>

  <action>
    1. Create `features/referrals/types.ts`:
       - Define TypeScript types: `ReferralItem`, `CreateReferralInput`, `CloseReferralLoopInput`, `ConsentedHistorySnapshot`.
    2. Create `features/referrals/schema.ts`:
       - Define Zod schema `createReferralSchema`:
         - `patient_id` (UUID), `visit_id` (optional UUID).
         - `referral_type` (`out_of_network` | `in_network`).
         - Out-of-network fields: `referred_to_name` (min 2 chars), `referred_to_facility` (optional string), `referred_to_specialty` (string), `referred_to_contact` (optional string).
         - In-network fields: `target_tenant_id` (optional UUID), `target_doctor_id` (optional UUID).
         - Clinical fields: `reason_for_referral` (min 3 chars), `provisional_diagnosis` (optional string), `urgency` (`routine` | `priority` | `urgent`), `clinical_summary` (optional string).
         - Consent field: `patient_consents_history_sharing` (boolean default false).
         - Letterhead field: `letterhead_mode` (`blank_paper` | `preprinted_letterhead` default `blank_paper`).
       - Define Zod schema `closeReferralLoopSchema`:
         - `referral_id` (UUID), `closure_notes` (min 3 chars), `return_date` (optional ISO date).
       - Define Zod schema `acknowledgeReferralSchema`: `referral_id` (UUID).
    3. Create `features/referrals/actions.ts`:
       - `createReferral(input)`:
         - Validates session via `getActiveMembership()`.
         - Validates input against `createReferralSchema`.
         - Fetches patient details, active medications (from latest prescription), and latest vitals.
         - If `in_network` and `patient_consents_history_sharing`:
           - Compiles structured snapshot of last 5 encounters (dates, chief complaints, diagnoses, vitals, meds).
           - Records DPDP consent entry in `consent_records` (`consent_type: 'referral_history_sharing'`, `granted: true`, `purpose: 'Clinical referral history summary sharing'`).
           - Saves structured snapshot in `consented_history_snapshot`.
         - Inserts new row into `public.referrals`.
         - Compiles branded referral letter PDF via `features/referrals/pdf/generator.ts`.
         - Saves storage path in `pdf_storage_path`.
         - Records audit log: `action: 'referral.create'`, `entityType: 'referral'`, `entityId: referral.id`.
       - `getOutboundReferrals()`:
         - Queries `referrals` where `tenant_id = session.tenantId`, ordered by `sent_at DESC`.
         - Includes joined patient full name, phone, UHID.
       - `getInboundReferrals()`:
         - Queries `referrals` where `target_tenant_id = session.tenantId`, ordered by `sent_at DESC`.
         - Includes originating clinic name and referring doctor name.
       - `acknowledgeReferral(referralId: string)`:
         - Updates status to `acknowledged`, sets `acknowledged_at = now()`.
       - `closeReferralLoop(input)`:
         - Updates referral status to `completed`, sets `closure_notes = input.closure_notes`, `completed_at = now()`, `closed_by = session.userId`.
         - Records audit log: `action: 'referral.close_loop'`.
       - `getReferralSignedUrl(referralId: string)`:
         - Verifies access; returns 3600s signed URL from `lib/storage/`.
       - `getPatientReferrals(patientId: string)`:
         - Queries all referrals for a specific patient under active tenant.
    4. Implement integration tests in `tests/referrals/referrals-flow.spec.ts`:
       - Test out-of-network referral creation.
       - Test in-network referral creation with DPDP consent logging and clinical snapshot assembly.
       - Test status transitions (`sent` -> `acknowledged` -> `completed`).
       - Test "Close the Loop" note recording.
       - Test multi-tenant isolation on referral queries.
  </action>
  <acceptance_criteria>
    - `features/referrals/` exports all schemas and server actions.
    - DPDP consent is logged to `consent_records` when history sharing is enabled.
    - Multi-tenant boundary is enforced.
