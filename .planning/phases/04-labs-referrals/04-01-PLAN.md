<objective>
Build the storage foundation, database migrations, and existing storage refactoring for Phase 4:
1. Establish Wave 0 test stubs across storage, labs, and referrals suites.
2. Create database migration `supabase/migrations/000013_labs_and_referrals.sql` creating private storage bucket `clinic-records` with multi-tenant RLS, plus tables `patient_documents`, `document_share_tokens`, and `referrals` with appropriate foreign keys and RLS policies.
3. Update `lib/db/types.ts` with complete TypeScript interfaces matching the migration.
4. Implement the unified Storage Provider abstraction in `lib/storage/` supporting both Supabase Storage and Cloudflare R2 (S3-compatible) via environment variable configuration (`STORAGE_PROVIDER=r2` or `R2_ACCOUNT_ID`).
5. Refactor existing prescription and billing PDF generators (`features/prescriptions/pdf/generator.ts` and `features/billing/pdf/generator.ts`) to use `lib/storage/` so all documents share a single storage pipeline.
6. Verify storage tests and typecheck pass without regressions.
</objective>

<threat_model>
| Threat ID | STRIDE Category | Component | Description | Severity | Mitigation |
|-----------|-----------------|-----------|-------------|----------|------------|
| T-04-01 | Elevation of Privilege / Tampering | `lib/storage/` & `storage.objects` | Path traversal or cross-tenant write via malicious relative path (e.g. uploading to another tenant's prefix). | High | Enforce deterministic `tenants/${tenantId}/...` path validation in `lib/storage/` and enforce Supabase storage RLS policy checking `split_part(name, '/', 2)::uuid IN (SELECT public.current_user_tenant_ids())`. |
| T-04-02 | Information Disclosure | Storage Bucket & Signed URLs | Unauthorized access to sensitive medical records or leaking S3/R2 credentials. | High | Bucket is strictly private; downloads require short-lived signed URLs (3600s TTL); R2 secrets are strictly server-side environment variables never exposed to client. |
| T-04-03 | Broken Object Level Auth | `patient_documents` table | Clinician in Tenant A querying or deleting document rows belonging to Tenant B. | High | Enforce PostgreSQL Row Level Security on `patient_documents` using `tenant_id IN (SELECT public.current_user_tenant_ids())` with server-side `getActiveMembership()` verification. |
</threat_model>

    2. Create `lib/storage/types.ts`:
       - Define `StorageUploadOptions`: `path: string`, `buffer: Buffer | Uint8Array`, `contentType: string`, `bucket?: string`, `upsert?: boolean`.
       - Define `StorageSignedUrlOptions`: `path: string`, `bucket?: string`, `expiresInSeconds?: number` (default 3600), `downloadFilename?: string`.
       - Define `StorageDeleteOptions`: `path: string`, `bucket?: string`.
       - Define `StorageProvider` interface with `name`, `upload`, `createSignedUrl`, `delete`, and `download`.
    3. Create `lib/storage/supabase-provider.ts`:
       - Implements `StorageProvider`.
       - Default bucket: `clinic-records`.
       - `upload`: calls `supabase.storage.from(bucket).upload(path, buffer, { contentType, upsert: options.upsert ?? true })`.
       - `createSignedUrl`: calls `supabase.storage.from(bucket).createSignedUrl(path, expiresInSeconds)`.
       - `delete`: calls `supabase.storage.from(bucket).remove([path])`.
       - `download`: calls `supabase.storage.from(bucket).download(path)`.
    4. Create `lib/storage/r2-provider.ts`:
       - Implements `StorageProvider`.
       - Uses `S3Client` configured with Cloudflare R2 endpoint: `https://${process.env.R2_ACCOUNT_ID}.r2.cloudflarestorage.com`.
       - Credentials: `accessKeyId: process.env.R2_ACCESS_KEY_ID`, `secretAccessKey: process.env.R2_SECRET_ACCESS_KEY`.
       - Bucket: `process.env.R2_BUCKET_NAME || 'clinic-records'`.
       - Implements `PutObjectCommand`, `getSignedUrl(s3, new GetObjectCommand(...))`, `DeleteObjectCommand`.
    5. Create `lib/storage/index.ts`:
       - Provider factory inspecting `process.env.STORAGE_PROVIDER === 'r2'` or presence of `process.env.R2_ACCOUNT_ID`.
       - Exports singleton factory `getStorageProvider()`.
       - Exports helper functions:
         - `uploadFile(options: StorageUploadOptions)`
         - `getSignedUrl(options: StorageSignedUrlOptions)`
         - `deleteFile(options: StorageDeleteOptions)`
         - `sanitizeStoragePath(tenantId: string, category: string, entityId: string, filename: string): string`
    6. Implement unit tests in `tests/storage/storage-provider.spec.ts` testing factory switching, path generation, and mock provider interactions.
