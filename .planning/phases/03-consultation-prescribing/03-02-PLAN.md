<objective>
Build the clinical consultation workspace and specialty templates engine for Phase 3:
1. Server Actions (`features/consultation/actions.ts`) and Zod schemas (`features/consultation/schema.ts`) for updating SOAP sections, specialty payloads, and follow-ups with tenant-isolation and audit logging.
2. Shared Vitals block with clinical abnormal badges, Chief Complaints hybrid chips, and Slide-Over Patient History Drawer with 1-click repeat.
3. Extensible Specialty Templates: General Physician review, Dental visual SVG Odontogram (`dental-odontogram.tsx`), and Pediatrics growth percentile calculator & IAP immunization checklist (`pediatrics-tools.tsx`).
4. Main Consultation Page (`app/(dashboard)/consultation/[id]/page.tsx`) with sticky jump bar, debounced auto-save, and follow-up chips.
</objective>

<threat_model>
| Threat ID | Category | Component | Description | Severity | Mitigation |
|-----------|----------|-----------|-------------|----------|------------|
| T-03-03 | Broken Access Control / State Bypass | `features/consultation/actions.ts` | Unauthorized staff attempting to modify a visit consultation note in another clinic or after sign-off without revision trail. | high | Check active clinic membership (`getActiveMembership`), enforce `requirePermission('consultations:edit')`, and verify tenant ownership in SQL queries. |
| T-03-04 | Injection & Prototype Pollution | `visits.specialty_data` (JSONB) | Malicious or malformed specialty payload injected into database corrupting JSONB structure. | high | Validate all specialty data strictly using Zod discriminated union schemas before database persistence. |
| T-03-05 | Data Integrity | Pediatric Growth Calculation | Erroneous calculations producing misleading growth percentiles. | medium | Use standard WHO LMS formula with verified reference lookup constants, tested via `tests/pediatrics/who-growth.spec.ts`. |
</threat_model>

       - `vitalsSchema`: systolic (50-250), diastolic (30-150), pulse (30-220), temperature (90-110), spo2 (50-100), weight (0.5-300), height (20-250), respiratory_rate (8-60). Add refine rule ensuring systolic > diastolic when both provided.
       - `chiefComplaintItemSchema`: symptom (string min 1), duration_val (number positive), duration_unit ('days'|'weeks'|'months'|'years'), notes (optional string).
       - `specialtyDataSchema`: discriminated union on `specialty`:
         - `general_physician`: general_exam (pallor, icterus, cyanosis, clubbing, lymphadenopathy, edema), systemic (cvs, rs, pa, cns).
         - `dental`: odontogram (array of tooth objects with tooth_number 11-48 / 51-85, condition_tags array, notes).
         - `pediatrics`: birth_history (gestational_age_weeks, birth_weight_kg, delivery_type, complications), head_circumference_cm, immunizations_given (string array).
       - `saveConsultationDraftSchema`: visit_id, vitals, chief_complaints, clinical_notes, specialty, specialty_data, investigations_advised, advice, follow_up (interval, date).

       - `saveConsultationDraft(input, clientOverride?, sessionOverride?)`: validates schema, verifies `consultations:edit` permission, checks tenant ownership, updates `visits` row, records audit log `consultation.draft_save`.
       - `recordFollowUp(input)`: inserts into `follow_ups` table with `tenant_id`, `patient_id`, `visit_id`, `follow_up_date`.
       - `getPatientConsultationHistory(patientId, currentVisitId)`: returns past completed visits, previous diagnoses, and past prescriptions for longitudinal context.
