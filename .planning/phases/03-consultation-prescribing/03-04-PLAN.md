<objective>
Build the server-side React-PDF generation pipeline, dual letterhead printing engine, and post-sign-off amendment lifecycle for Phase 3:
1. Server-side PDF Compilation: Clean A4 prescription document built with `@react-pdf/renderer` in Node.js runtime, bundled safely via `serverExternalPackages`.
2. Dual Letterhead Engine: "Print on Blank Paper" (full clinic header, logo, contact, reg no) vs "Print on Pre-Printed Letterhead" (110pt / ~39mm top margin and 60pt / ~21mm bottom margin offset for clinic physical letterhead pads).
3. Supabase Storage & Signed URLs: Private `prescriptions` bucket storage with 3600-second time-limited signed URLs, tenant isolation, and audit logging.
4. Post-Sign-Off Amendment Lifecycle: Re-opening completed visits creates an immutable snapshot row in `visit_revisions`, increments prescription version (`v2`, `v3`), and stamps the PDF with an "Amended on [Date]" watermark and doctor's rationale.
5. In-App Preview Modal: Accessible dialog (`pdf-preview-modal.tsx`) with instant letterhead switching, native print invocation, and direct PDF download.
6. Comprehensive Integration Suite: `tests/integration/prescription-versioning.spec.ts` testing PDF binary buffer compilation, dual letterhead offsets, revision snapshots, and versioning.
</objective>

<threat_model>
| Threat ID | Category | Component | Description | Severity | Mitigation |
|-----------|----------|-----------|-------------|----------|------------|
| T-03-08 | Information Disclosure / Unauthorized Document Access | Supabase Storage & `app/api/visits/[id]/prescription-pdf/route.ts` | Attackers accessing sensitive patient medical prescriptions via direct storage URLs or cross-tenant route requests. | high | Use private Supabase Storage bucket `prescriptions`, issue short-lived signed URLs (3600s TTL), and authenticate user session and clinic tenant membership before generating or serving any PDF. |
| T-03-09 | Non-repudiation / Tampering | Consultation & Prescription Revision Lifecycle (`features/consultation/actions.ts`) | A doctor or malicious actor altering a finalized prescription or consultation note without leaving an audit trail or invalidating the issued document. | high | Completed visits are immutable by default. Any amendment requires entering a mandatory reason, writes a complete JSON state snapshot to `visit_revisions`, increments prescription version (`v2`), and prominently stamps the resulting PDF with "Amended on [Date]". |
</threat_model>

         - Uploads buffer to private Supabase Storage bucket `prescriptions` under `${tenant_id}/${visit_id}/rx_v${version}.pdf` with `upsert: true`.
         - Issues signed URL valid for 3600 seconds (`supabase.storage.from("prescriptions").createSignedUrl(storagePath, 3600)`).
         - Records audit event `prescription.generate_pdf` with `visit_id`, `version`, `letterhead_mode`.
         - Returns signed URL and storage path.
    4. Create Route Handler `app/api/visits/[id]/prescription-pdf/route.ts`:
       - Authenticates user session with `createClient()` from `@/lib/supabase/server`.
       - Validates clinic tenant membership via `user_tenant_memberships`.
       - Fetches visit, patient, doctor, diagnosis, and prescription details.
       - Parses query params `letterhead` (`blank_paper` | `preprinted_letterhead`, default: `blank_paper`) and `download` (`true` | `false`).
       - Compiles PDF buffer and returns `Response` with `Content-Type: application/pdf` and `Content-Disposition: inline; filename="Rx-[UHID]-[VisitID].pdf"` (or `attachment` if `download=true`).
  </action>

    1. Enhance `features/consultation/actions.ts`:
       - `completeAndSignConsultation(visitId: string)`:
         - Verifies authenticated doctor or authorized clinic staff.
         - Ensures at least one diagnosis or clinical note exists.
         - Finalizes prescription items (`status = 'issued'`, `version = 1`).
         - Generates initial archival PDF (`v1`) in storage bucket `prescriptions`.
         - Updates visit status to `completed` and records `completed_at = now()`.
         - Records audit event `visit.complete_and_sign`.
       - `reopenVisitForAmendment(visitId: string, reason: string)`:
         - Verifies authenticated doctor is assigned doctor or clinic owner.
         - Validates `reason` (min 10 characters).
         - Fetches complete current state of the consultation (clinical notes, vitals, diagnoses, prescriptions, specialty data).
         - Inserts snapshot into `visit_revisions` table:
           `{ tenant_id, visit_id, revision_number, snapshot: current_json_state, reason, amended_by: auth.uid(), created_at: now() }`.
         - Updates visit: `status = 'in_consultation'`, `is_amended = true`.
         - Records audit event `visit.reopen_for_amendment`.
       - `finalizeVisitAmendment(visitId: string)`:
         - Increments prescription version (`version = version + 1`).
         - Regenerates archival PDF stamped with `Amended on [Date] (v[version]) — Reason: [reason]`.
         - Sets visit status back to `completed`.
         - Records audit event `visit.amend_finalized`.
    2. Create `components/consultation/amendment-modal.tsx`:
       - Accessible dialog triggered when doctor clicks `Edit Completed Visit` button on a completed consultation workspace.
       - Header:
         - Icon: `AlertTriangle` in amber/yellow.
         - Title: "Reopen Visit for Clinical Amendment"
         - Subtitle: "This visit was completed and signed on {completedDate}. Editing will create an audited revision snapshot (v{currentVersion + 1}) and stamp the revised prescription as amended."
       - Body:
         - Form field: "Reason for Amendment (Required for Medical Records Audit)"
         - Textarea: `placeholder="e.g. Added antibiotic following patient's callback regarding persistent high fever"`, min 10 characters.
         - Helper text: "This explanation will be permanently recorded in the revision history and printed on the amended prescription watermark."
       - Actions:
         - Safe button: `Cancel Amendment` (outline variant, min-h-[44px]).
         - Proceed button: `Confirm & Reopen for Amendment` (destructive/brand variant with AlertTriangle, min-h-[44px], disabled if reason length < 10).
