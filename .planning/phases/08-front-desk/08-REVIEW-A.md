## Checked and fine

- Visit state machine (000100): TS and SQL tables match for all 98 combinations (spec reads the DB); trigger is `BEFORE UPDATE OF status`, `WHEN` distinct, definer, revoked; signed reopen only for signed visits; `start_consultation` and `complete_visit` follow the command pattern, idempotent, one audit row, `already_started` and `already_completed` replays correct.
- `register_patient` and `search_patients`/`find_patient_duplicates` (000101, 000104, 000105): closed key set, objection stored through the existing stamp and audit triggers; wildcard and digit rules sound; the definer duplicate lookup is guarded by the active full clinic and `patients:view` and returns the minimal projection only.
- Realtime (000102): policy admits only an active member holding `appointments:view` of the clinic named in the topic when the clinic is `full`; no INSERT policy; payload is `{kind, visit_id}`; the send is wrapped so a fault cannot roll back a write; vitals first-write is an UPDATE (row pre-created), so the vitals trigger does fire.
- Staff scheduling commands (000103): reschedule, cancel, no-show, confirm, waitlist add and promote: guard order, claim, lock, conflict evaluation (off duty, blocked, taken independent; overrides clear only their own), deadlock retry, SLOT_IN_PAST, replay and mismatch hashing, clinic-zone message times all consistent. Promotion claims an entry with `SKIP LOCKED` (one entry once); past slots are not promoted.
- Slot rules and clinic zone: `available_slots_core` and `slot_conflicts` read the same effective schedule (NULL = column default), grid and conflict checks in `tenants.timezone`, exclusion of the visit's own slot, 90-day horizon on the patient link; `consume_reschedule_token` revalidates shifts, blocks, own duration and the constraint, advisory lock per doctor.
- `UPDATE` grant narrowing: all remaining user-client writers of `visits` write only `specialty`, `metadata`, `updated_at` (draft save); API v1 and webhooks use the service role and are subject to the state-machine trigger only.
- Command client (`lib/commands/use-command.ts`): one id per submit; timeout and single retry with the same id; definite refusals not retried; late answers ignored; offline sends nothing and spends no id; unresolved state keeps the id; double submit returns the in-flight promise; per-row hooks in Today so concurrent rows do not share a runner.
- Walk-in, booking, reschedule, cancel, no-show sheets: slot refusal resets the id then re-sends with the override flags (new request, nothing written by the refused one); overbook new-patient path creates one patient via `register_and_book`; Enter-to-add focus handling; closing removes sheet params with `replace`.
- Today live: coalescing, polling fallback and resume, `refreshWhenReachable` guards the offline navigation; optimistic check-in override applies only while the server row still has the old status (no stuck or duplicated rows); rows keyed by visit id, lanes derived from status.
- Roles: receptionist and admin get no consult action (UI from `rowActions`, DB requires `consultations:edit` and `appointments:edit`); nurse triage actions match `vitals:edit`; consult route gated on `consultations:view`; clinic switcher writes the cookie only after an RLS membership read, attributes HttpOnly, SameSite=Lax, 400 days.
- Deleted v1 screens: `/`, `/queue`, `/cabin`, `/calendar`, `/patients/new` redirect from `next.config.ts` or the page; internal links, notification links (`/calendar`, `/queue?tab=waitlist` in stored rows) still resolve through the redirects; sign-and-bill returns to `/today?mode=doctor`; patient profile links carry `?book=1&patient=`.
- Tests sampled (state-machine parity, live hook, save-state, no-client-chains, rewritten M0 booking and cancel e2e): they assert outcomes (rows, statuses, counts), not renders; the grep spec is a deliberate structural rule with a self-check. Gaps: nothing covers A-1 (partial re-record), A-2 (block over a booked slot), A-3 (late arrival into a rebooked slot), A-4 (unbilled completed visit).
