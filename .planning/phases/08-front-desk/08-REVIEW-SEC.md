# V2-08 Front desk: adversarial security review

Scope: `git diff 9ce25d7..HEAD` (HEAD `2967c33`, branch `v2/phase-08-front-desk`), migrations 000100 to 000105 and the
listed app paths. Reviewer: isolated Claude reviewer with no implementer context. Method: I read the source, then ran
probes as `authenticated` or `anon` on the LOCAL stack only (`127.0.0.1:54322`, migrations at 000105), each inside one
`BEGIN ... ROLLBACK` with synthetic fixtures (clinic A: owner, doctor, receptionist, nurse; clinic B: owner, doctor;
one user who belongs to both). Probe scripts are in the session scratchpad: `probe1.sql` to `probe4.sql`. No data was
committed. Only the `audit_logs` id sequence moved.

**Result: no Critical or High.** Every attempt to reach clinic B from clinic A was refused, through the commands, the
definer reads, the Realtime policy, the clinic switcher and the token functions (see "Attempted and refused"). What
remains are **inside-clinic integrity and audit gaps**: tables that the phase's commands and command-only audit
actions were meant to own can still be written directly through PostgREST.

## Attempted and refused

- Clinic A receptionist: `cancel_visit` with `p_tenant_id=B` on B's visit raised `VISIT_NOT_FOUND`, and with `p_tenant_id=A` on B's visit also `VISIT_NOT_FOUND`.
- `reschedule_visit(A, <A visit>, ..., p_doctor_id=<B doctor>, overbook=true)` raised `DOCTOR_NOT_FOUND`. With `p_doctor_id=<A receptionist>` it also raised `DOCTOR_NOT_FOUND` (checked before overbook).
- `add_to_waitlist(A, <B patient>)` raised `PATIENT_NOT_FOUND`. `add_to_waitlist(A, <A patient>, doctor=<B doctor>)` raised `DOCTOR_NOT_FOUND`.
- `promote_waitlist_entry(..., p_doctor_id=<receptionist>, p_overbook=true)` raised `DOCTOR_NOT_FOUND` (via `step_create_visit`, G-9).
- `register_patient(p_tenant_id=B)` from an A-only user raised `PATIENT_NOT_FOUND`.
- `start_consultation` as receptionist raised `FORBIDDEN` (needs `consultations:edit` and `appointments:edit`).
- Direct `UPDATE visits SET status=...` and `SET scheduled_at=...` as receptionist raised `permission denied for table visits` (the column grant works).
- `find_patient_duplicates('<B mobile>', '<B name>', '<B dob>')` from an A member returned 0 rows (definer, filtered by tenant). `search_patients('Bravo')` returned 0.
- `available_slots(<B doctor>, date)` from an A member returned 0 (A doctor returned 27). `slot_suggestion_context(<B doctor>, <B patient>)` returned 0 samples and a null band.
- `private.available_slots_core(...)` called directly raised `permission denied`.
- Dual member with header pinned to A: `confirm_appointment(B, ...)` raised `VISIT_NOT_FOUND`, and the B-phone duplicate lookup returned 0.
- Dual member with no header: `authz.active_tenant_id()` returned NULL, and search returned 0. A header naming a clinic the user does not belong to also gave active tenant NULL.
- Realtime: `authz.today_topic_allowed('today:<B>')` for an A member returned false (true for its own `today:<A>`). Anon got `permission denied for schema authz`. There is no INSERT policy on `realtime.messages`. The topic regex is anchored and lower-case only. Payloads are `{kind, visit_id}` only (pgTAP `today_signals`). The policy also requires an active membership and a `full` clinic.
- Anon: `search_patients`, `find_patient_duplicates` and `available_slots` all raised `permission denied for function`. `get_reschedule_slots(<bogus 40-char token>)` returned `not_found`.
- `switchClinic`: the membership is read under RLS with `status='active'` and the value written is the database's id. Server actions get Next's Origin check. A foreign id, or a header pinned to a clinic the caller left, is ignored by `authz.active_tenant_id()`.
- `/api/patients/search`: the tenant comes from the session (`resolveServiceContext("patients:view")`), never from the query. The response is the minimal projection with `Cache-Control: private, no-store`, and error bodies are fixed text. The INVOKER function strips `% _ * \ , ( )`, so there is no wildcard oracle.
- `/consultation/[id]`: a role without `consultations:view` is redirected before the visit is read, in both the layout and the page.
- Staff-triggered patient WhatsApp spam through repeated `reschedule_visit(p_notify=true)` to distinct times: each send gets a new dedupe key, but dispatch is capped by the clinic's monthly messaging quota (`lib/messaging/governance.ts:96-105`). Bounded.
- `private.name_normalize` EXECUTE for `authenticated`: the function is pure and the `private` schema is not API-exposed. Verified callable only from SQL, with no data access.
