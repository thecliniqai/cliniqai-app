<objective>
Implement the Two-Way WhatsApp Bot, 23-Event Outbox Triggers, and Public Tokenized Sharing:
1. Build the inbound webhook route `app/api/webhooks/messaging/[provider]/route.ts` with signature validation supporting Twilio, Gupshup, MSG91, and `dev` simulator.
2. Implement two-way interactive button handling:
   - `[Confirm]`: updates appointment to `confirmed`, audits action, sends confirmation template.
   - `[Cancel]`: marks appointment `cancelled` with `cancellation_reason: 'patient_whatsapp_bot'`, frees doctor's slot, alerts front desk waitlist, and sends polite cancellation acknowledgement.
   - `[Reschedule]`: generates tokenized link `/reschedule/[token]` and sends in-app alert to front desk.
   - Unhandled conversational text: triggers polite fallback auto-reply and notifies front desk notification drawer.
3. Build the public mobile reschedule route `app/reschedule/[token]/page.tsx` with date/slot selection and booking execution.
4. Build the public mobile document viewer `app/r/[token]/page.tsx` + `app/api/r/[token]/route.ts` supporting Prescriptions, Lab Reports, Invoices, and Referrals with access counter and expiration enforcement.
5. Wire 23-event outbox triggers into appointment booking, cancellation, rescheduling, prescription signing, and billing mutations.
6. Verify two-way bot and tokenized sharing test suites pass.
</objective>

<threat_model>
| Threat ID | STRIDE Category | Component | Description | Severity | Mitigation |
|-----------|-----------------|-----------|-------------|----------|------------|
| T-05-04 | Spoofing / Tampering | Inbound Messaging Webhook | Attacker sending forged webhook requests to cancel appointments or spoof patient responses. | High | Enforce cryptographic signature verification (Twilio HMAC-SHA1, Gupshup token, MSG91 auth key) before processing webhook payloads; reject unverified requests with 403. |
| T-05-05 | Information Disclosure | Public Document Viewer (`/r/[token]`) | Brute-forcing token URLs to access sensitive patient health records or prescriptions. | High | Generate high-entropy 64-character hexadecimal tokens; enforce 7-day default expiry; log access count and IP metadata; reject expired or revoked tokens with 410. |
| T-05-06 | Denial of Service | Calendar Slot Release (`[Cancel]`) | Malicious actor repeatedly cancelling appointments using random phone numbers. | Medium | Verify that incoming phone number strictly matches the active patient appointment before updating status; rate-limit webhook endpoint. |
</threat_model>

    Build the inbound webhook handler and button action processors:
    1. In `app/api/webhooks/messaging/[provider]/route.ts`:
       - Verify provider signature based on `params.provider`:
         - `dev`: allow local development/testing without signature.
         - `twilio`: validate `X-Twilio-Signature` using `TWILIO_AUTH_TOKEN`.
         - `gupshup`: validate security token header.
         - `msg91`: validate auth key header.
       - Extract sender phone number, message body, button payload (`btn_confirm`, `btn_cancel`, `btn_reschedule` or text `1`, `2`, `3`).
       - Find active upcoming appointment matching patient phone number.
       - If button is `[Confirm]`:
         - Update appointment status to `confirmed`.
         - Log audit entry: `action = 'appointment_confirmed_whatsapp'`.
         - Send confirmation reply message.
       - If button is `[Cancel]`:
         - Update appointment status to `cancelled`, `cancellation_reason = 'patient_whatsapp_bot'`.
         - Release doctor calendar slot immediately.
         - Check waitlist: if patients are waitlisted for this date/doctor, create in-app notification `waitlist_slot_freed` for front desk.
         - Log audit entry: `action = 'appointment_cancelled_whatsapp'`.
         - Send cancellation acknowledgement message.
       - If button is `[Reschedule]`:
         - Generate 24-hour tokenized reschedule link: `${APP_URL}/reschedule/${token}`.
         - Send reply with the link.
         - Create in-app notification for front desk (`reschedule_requested`).
       - If conversational text / unhandled inquiry:
         - Send polite triage template: *"We received your message. For urgent queries please call [Clinic Phone]. Our desk will follow up shortly."*
         - Create in-app notification (Event #18 `whatsapp_reply`) for front desk with verbatim text.
    2. Update `tests/messaging/two-way-bot.spec.ts` with tests verifying webhook signature validation, confirm flow, cancel slot release, and fallback triage.
