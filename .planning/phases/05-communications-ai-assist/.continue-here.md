# BLOCKING CONSTRAINTS — Read Before Anything Else

> These are not suggestions. Each constraint below was discovered through failure.
> Acknowledge each one explicitly before proceeding.

- [ ] CONSTRAINT: Visits Table Reference — In ClinicOS, scheduled appointments are stored in `public.visits` (`origin_type = 'scheduled'`). There is NO `public.appointments` table. Any queries or relations must reference `public.visits`.
- [ ] CONSTRAINT: IST Timezone Arithmetic — Messaging quiet hours are evaluated in IST (UTC+05:30). Use epoch offset `time.getTime() + 5.5 * 3600 * 1000` with `getUTCHours()` or `Date.UTC()` to avoid server host timezone pollution.
- [ ] CONSTRAINT: Unique Threat IDs — Threat model entries in GSD plans must be numbered sequentially across the phase (`T-05-01` through `T-05-12`) to satisfy the GSD pre-dispatch threat ID gate (#4683).

## Critical Anti-Patterns

| Pattern | Description | Severity | Prevention Mechanism |
|---------|-------------|----------|---------------------|
| Referencing `appointments` table | `appointments` does not exist in the schema | blocking | Always use `public.visits` with `origin_type = 'scheduled'` and `visits.id` |
| Local `getTimezoneOffset()` in quiet hours | Causes test or production failures on non-UTC/non-IST host servers | blocking | Use explicit epoch-based UTC offset (`IST_OFFSET_MS = 5.5 * 3600 * 1000`) |
| Duplicate Threat IDs across plans | Causes GSD execution init gate failures | advisory | Threat IDs are strictly unique per phase (`T-05-01` .. `T-05-12`) |
