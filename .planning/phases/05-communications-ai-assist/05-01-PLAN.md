  <action>
    Implement the governance rules, resilient queue dispatcher, and cron recovery:
    1. `lib/messaging/governance.ts`:
       - `evaluateMessageEligibility(tenantId, eventType, patientId, requestedChannel)`:
         - Checks Company Master Policy & Tenant Messaging Config: returns `{ eligible: boolean, resolvedChannel: 'whatsapp' | 'sms' | 'in_app', templateId: string, reason?: string }`.
         - Evaluates quiet hours (21:00 to 08:00 IST): non-urgent notifications calculate `nextRetryAt` for 08:01 IST.
         - Checks monthly message quota: if `messages_sent_this_month >= monthly_quota`, suppresses external messaging and creates Event #21 In-App quota warning.
         - Evaluates patient preferences (`whatsapp_opt_out`, `preferred_language`).
    2. `lib/messaging/dispatcher.ts`:
       - `enqueueMessage(payload)`: Inserts a row into `communication_queue` with status `pending`.
       - `dispatchPendingQueue(limit = 20)`:
         - Selects pending messages where `status = 'pending'` or `(status = 'failed' AND retry_count < max_retries AND next_retry_at <= now())`.
         - Marks rows as `processing`.
         - Calls active `MessagingProvider`.
         - On success: updates row to `sent`, records `sent_at`, logs audit entry in `audit_logs` (`action = 'communication_sent'`).
         - On failure: increments `retry_count`, calculates exponential backoff (`next_retry_at = now() + (retry_count * 5 minutes)`), updates status to `failed` (or `dead_letter` if max retries exceeded).
         - Conditional SMS fallback: if WhatsApp delivery fails on `appointment_booked` or `appointment_rescheduled` and fallback is permitted, immediately enqueues deduplicated SMS fallback row.
    3. `app/api/cron/dispatch-communications/route.ts`:
       - Route handler triggered via GET/POST.
       - Validates `Authorization: Bearer <CRON_SECRET>`.
       - Calls `dispatchPendingQueue(50)` and returns JSON summary `{ processed: number, succeeded: number, failed: number }`.
    4. Update `tests/messaging/outbox-queue.spec.ts` with integration tests verifying outbox enqueueing, dispatch lifecycle, quiet hours, and backoff.
  </action>
