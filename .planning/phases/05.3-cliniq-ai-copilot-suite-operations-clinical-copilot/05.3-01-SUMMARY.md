## 1. Executive Summary

Wave 1 of Phase 05.3 establishes the architectural, regulatory, and backend foundation for the CliniQ AI Copilot Suite. It installs Vercel AI SDK v4, defines typed Zod schemas for operations and clinical interactions, creates a DPDP Act 2023 compliant PII scrubbing utility, builds a grounded product help knowledge manifest, implements 7 server-side operations tools and 2 clinical tools with strict RBAC enforcement, and deploys Next.js 15 App Router streaming route handlers with sliding-window token pruning.

All 4 planned tasks were executed test-first and committed atomically:
1. **AI SDK Dependencies, Typed Schemas & Universal Gateway Resolver (`package.json`, `lib/ai/types.ts`, `lib/ai/client.ts`):** Installed `ai@^4.0.0`, `@ai-sdk/react@^1.0.0`, and `@ai-sdk/openai@^1.0.0`. Added Zod schemas for `Icd10CandidateSchema`, `Icd10RecommendationSchema`, `ScreenContextSchema`, `BookingPreviewDetailsSchema`, `ReschedulePreviewDetailsSchema`, and `CancelPreviewDetailsSchema`. Implemented `getAiGatewayModel()` returning a configured LanguageModel instance and added operations tool mocking to `MockAiProvider`.
2. **DPDP Act PII Sanitizer & Grounded Product Manifest (`lib/ai/sanitizer.ts`, `lib/ai/knowledge/product-manifest.ts`):** Built regex scrubbers for Indian mobile numbers, Aadhaar, and ABHA IDs. Implemented `sanitizePatientContextForPrompt` stripping direct identifiers while retaining age, sex, vitals, and chronic conditions. Built `getProductHelpAnswer` mapping verified navigation steps and explicitly declining unsupported features (crypto, in-patient ward beds, autonomous prescribing).
3. **Server-Side Tool Definitions with RBAC Enforcement (`lib/ai/tools/operations-tools.ts`, `lib/ai/tools/clinical-tools.ts`):** Implemented `assertRoleAllowed` throwing `UNAUTHORIZED_ROLE`. Created operations tools (`search_patients`, `check_availability`, `request_appointment_booking`, `reschedule_appointment`, `cancel_appointment`, `get_queue_status`, `get_product_help`) with two-phase preview confirmation cards. Created clinical tools (`suggest_icd10`, `get_catch_up_summary`) blocking nurses from diagnostic coding.
4. **Next.js 15 App Router Streaming Route Handlers & Unit Test Suite (`app/api/ai/operations-copilot/route.ts`, `app/api/ai/clinical-copilot/route.ts`, `tests/ai/gateway-tools.spec.ts`):** Created streaming POST route handlers with `export const maxDuration = 30`, token-frugal sliding-window pruning (`messages.slice(-5)`), `maxSteps: 3`, and mandatory statutory clinical disclaimer appending. Created 13-assertion unit test suite verifying sanitization, manifest lookup, RBAC gates, and preview card staging.

## 4. Key Design Decisions

1. **Two-Phase Action Staging via Preview Payloads (D-05, D-06):** Mutating tools (`request_appointment_booking`, `reschedule_appointment`, `cancel_appointment`) do not commit changes immediately to the database. Instead, they return `{ status: 'preview_ready', requires_confirmation: true, details: ... }` which the client UI renders as interactive confirmation cards.
2. **DPDP Data Minimization Boundary (D-15, T-05.3-01):** Direct identifiers (names, phones, Aadhaar, ABHA, addresses) are stripped before sending prompt payloads to external LLM providers. Only clinical tokens (age, sex, vitals, chronic conditions) are transmitted.
3. **Server-Side RBAC Enforcement on Every Tool (D-09, T-05.3-02):** Role validation occurs inside the tool execution function itself using `assertRoleAllowed`, ensuring that natural language prompt injection cannot bypass role boundaries.
4. **Mandatory Clinical Advisory Disclaimer (D-19, T-05.3-04):** Every response from the clinical copilot streaming route is required to conclude with the statutory disclaimer reminding clinicians that CliniQ AI is an informational assistant.
