<objective>
Implement the Patient Visit History timeline on the Patient Detail Page (`/patients/[id]`):
1. Create `getPatientVisitHistory(patientId: string)` in `features/patients/actions.ts` querying all clinical visits for a patient under the active tenant, including treating doctor details, consultation diagnoses, active prescriptions, and billing status.
2. Build `PatientVisitHistory` component (`components/patients/patient-visit-history.tsx`) displaying a chronological card-based timeline with chief complaints, diagnoses, vitals chips, medication lists, and direct 1-tap `[Print Rx]` and `[Receipt]` actions.
3. Integrate `PatientVisitHistory` into `app/(dashboard)/patients/[id]/page.tsx`, replacing the static placeholder.
4. Add unit and integration tests in `tests/patients/visit-history.spec.ts`.
</objective>

<threat_model>
| Threat ID | Category | Component | Description | Severity | Mitigation |
|-----------|----------|-----------|-------------|----------|------------|
| T-03.2-01 | Information Disclosure / Cross-Tenant Leak | `getPatientVisitHistory` | An authenticated user from Tenant B attempting to view clinical visit history of a patient belonging to Tenant A. | high | Enforce `getActiveMembership()` and add `.eq("tenant_id", session.tenantId)` on all queries with database-level RLS backup. |
| T-03.2-02 | Broken Access Control / Clinical Tampering | `PatientVisitHistory` actions | Non-clinical staff attempting to edit clinical notes or alter finalized prescriptions. | medium | Pass user role to `PatientVisitHistory`; render read-only view for non-doctors, and enforce server action authorization on consultation mutation endpoints. |
</threat_model>

<tasks>
1. **Data Access Function in `features/patients/actions.ts`**:
   - Implement `getPatientVisitHistory(patientId: string)`:
     - Derives session via `getActiveMembership()`.
     - Queries `visits` table where `patient_id = patientId` and `tenant_id = session.tenantId`, ordered by `scheduled_at` / `created_at` DESC.
     - Fetches related `consultation_diagnoses`, `prescriptions` (latest version with `prescription_items`), and `invoices` (status, total_amount, balance_due).
     - Resolves treating doctor information (`full_name`, `qualifications`, `medical_council_reg_no`) from `memberships`.
   - Add type definitions for `PatientVisitHistoryItem`.

2. **Interactive UI Component in `components/patients/patient-visit-history.tsx`**:
   - Build `PatientVisitHistory` with TailAdmin-styled timeline design conforming to `DESIGN.md`:
     - Clean chronological feed with date badge, time, token number, and status indicator (`completed`, `in_consultation`, `waiting`, `cancelled`).
     - Doctor header: Doctor full name, primary specialty, and qualifications.
     - Clinical Summary:
       - Vitals badges (BP, Pulse, Temp, SpO2, Weight) with normal/abnormal visual styling.
       - Chief complaints chips.
       - Diagnoses list with ICD-11 / SNOMED CT codes.
       - Prescribed medications preview (name, dosage, timing, duration).
       - Billing status badge (Paid in emerald, Balance due in amber).
     - Action toolbar per encounter:
       - `[Print Rx]` button linking to `/api/visits/[id]/prescription-pdf` in new tab.
       - `[Receipt]` button linking to `/api/invoices/[id]/receipt-pdf` in new tab.
       - `[Review / Open Encounter]` button.
     - Empty state: When patient has 0 visits, render friendly guidance card with "Book Appointment" and "Add to Queue" shortcuts.

3. **Page Integration in `app/(dashboard)/patients/[id]/page.tsx`**:
   - Fetch visit history asynchronously via `getPatientVisitHistory(patient.id)`.
   - Replace the static text in the Clinical History card with `<PatientVisitHistory visits={visits} userRole={membership.role} />`.
   - Ensure responsive layout looks clean across mobile, tablet, and desktop workstations.

4. **Testing in `tests/patients/visit-history.spec.ts`**:
   - Verify `getPatientVisitHistory` returns visits sorted in reverse chronological order.
   - Verify queries enforce tenant isolation (`tenant_id` check).
   - Verify UI component formats vitals, diagnoses, and medication items properly.
</tasks>
