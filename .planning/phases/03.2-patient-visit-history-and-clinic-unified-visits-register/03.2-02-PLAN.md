<objective>
Build the Unified Clinic Visits Register Page (`/visits`):
1. Create `getClinicVisitsRegister(filters)` in `features/visits/actions.ts` with date range filtering, doctor filtering, status filtering, fuzzy search, and summary metrics.
2. Build `VisitsRegisterView` (`components/visits/visits-register-view.tsx`) with TailAdmin light theme tokens, date range presets, summary stats strip, and an interactive table with instant PDF print actions.
3. Build `ReadOnlyEncounterModal` (`components/visits/read-only-encounter-modal.tsx`) allowing non-clinical roles (nurses, receptionists, billing) to inspect visit records without editing privileges.
4. Add "Visits" to sidebar navigation (`components/layout/app-sidebar.tsx`).
5. Add unit and integration tests in `tests/visits/clinic-visits-register.spec.ts`.
</objective>

<threat_model>
| Threat ID | Category | Component | Description | Severity | Mitigation |
|-----------|----------|-----------|-------------|----------|------------|
| T-03.2-03 | Information Disclosure | `/visits` route | Cross-tenant data leakage if date or search queries do not strictly scope to active clinic tenant ID. | high | Always derive tenant context from `getActiveMembership()` and bind `.eq("tenant_id", session.tenantId)` on all Supabase queries. |
| T-03.2-04 | Unauthorized Data Modification | `/consultation/[id]` access | Receptionists or nurses opening `/visits` and attempting to alter clinical diagnosis or prescription items. | high | Route doctors to `/consultation/[id]` while rendering `ReadOnlyEncounterModal` for non-doctors. Enforce server-side mutation guards on all clinical save endpoints. |
| T-03.2-05 | Denial of Service / Slow Queries | Unbounded Visits Query | Clinic querying months of visits causing unindexed table scans or heavy memory consumption. | medium | Implement default date bounds (defaults to today / past 7 days) and server-side pagination with limit/offset. |
</threat_model>

<tasks>
1. **Filter Schema & Data Access in `features/visits/actions.ts`**:
   - Define `visitsFilterSchema` in `features/visits/schema.ts` supporting `datePreset`, `startDate`, `endDate`, `doctorId`, `status`, `specialty`, `searchQuery`, `page`, `pageSize`.
   - Implement `getClinicVisitsRegister(input)`:
     - Derives session via `getActiveMembership()`.
     - Builds date filters based on selected preset or custom dates.
     - Performs paginated query on `visits` joined with `patients`, `memberships` (doctor details), `consultation_diagnoses` count, `prescriptions`, and `invoices`.
     - Calculates summary metrics: total visits, completed count, in-consultation count, and total billed revenue for the filtered period.
     - Fetches active doctor list in the clinic for the doctor dropdown filter.

2. **Master Visits Register View in `components/visits/visits-register-view.tsx`**:
   - Filter Toolbar:
     - Date Presets: `Today`, `Yesterday`, `Last 7 Days`, `This Month`, `Custom Range`.
     - Custom Date Range Picker (From Date & To Date).
     - Doctor Select Dropdown (All Doctors / Specific Doctor).
     - Status Dropdown (All Statuses, Waiting, In Consultation, Completed, Cancelled).
     - Search Input (Debounced search by patient name, phone, or UHID).
   - Summary Metrics Cards:
     - Total Visits in Period.
     - Completed Consultations (with emerald badge).
     - In Consultation / Waiting outside.
     - Total Revenue / Billed Amount (₹).
   - Master Table:
     - Columns: Date & Time, Patient Details (Name, Age, Sex, Phone, UHID), Doctor (Name & Specialty), Diagnoses / Chief Complaints summary, Prescriptions (Badge with 1-click download), Payment Status (Paid / Unpaid), Actions.
     - Actions:
       - `[Print Rx]` button linking to `/api/visits/[id]/prescription-pdf` in new tab.
       - `[Receipt]` button linking to `/api/invoices/[id]/receipt-pdf` in new tab.
       - `[Open Encounter]` button triggering role-based routing or read-only modal.

3. **Role-Based Encounter Preview (`ReadOnlyEncounterModal`)**:
   - For non-doctors (receptionists, nurses, billing staff), clicking `[Open Encounter]` opens a modal showing:
     - Patient demographics banner.
     - Vitals recorded at check-in.
     - Chief complaints and clinical notes (read-only).
     - Diagnoses recorded by the doctor.
     - Medication schedule and instructions.
     - Follow-up date and billing status.
     - Direct PDF download buttons.
   - For doctors and owners, clicking `[Open Encounter]` navigates directly to `/consultation/[id]` for clinical review or amendment.

4. **Navigation & Sidebar Integration**:
   - Update `components/layout/app-sidebar.tsx`:
     - Add `Visits` item with `FileText` icon under Operations for all roles.
     - Ensure active route highlight when on `/visits`.

5. **Testing & Verification in `tests/visits/clinic-visits-register.spec.ts`**:
   - Test date preset calculation (Today, Yesterday, Last 7 Days, This Month).
   - Test search filtering by patient name, phone, and UHID.
   - Test multi-tenant isolation ensuring queries cannot return visits from another tenant.
   - Test role-based action determination.
</tasks>
