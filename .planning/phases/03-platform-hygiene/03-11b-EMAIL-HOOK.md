## What shipped

- **`lib/email`.**
  - `EmailSender.send({ to, subject, html, text, tag }) → { providerMessageId }`.
  - `SesEmailSender`: SESv2 `SendEmailCommand`, the `category` message tag, client injectable. `createSesClient`
    builds the client: region constant `ap-south-1`, explicit credentials from `SES_*`, 1.5 s connect / 3 s request
    timeouts, 2 attempts.
  - `MailpitEmailSender`: loopback `POST ${MAILPIT_API_URL}/api/v1/send`. It refuses, at construction, a URL that is
    not loopback http(s) and any tier outside development | test | e2e | ci.
  - `DisabledEmailSender`: throws `EmailDisabledError`.
  - Errors carry a code (SDK error name, `mailpit_http_<status>`), never provider text: SES messages can quote the
    recipient.
  - `getEmailSender(env = serverEnv())` picks the sender.
- **Templates (`lib/email/templates/auth.ts`).**
  - signup, recovery, invite and email change carry the code only, with no link.
  - `password_changed` is a code-free notice.
  - The HTML equals `supabase/templates/*.html` with the code in place of `{{ .Token }}`. A spec compares them.
  - The code must be digits only (6 to 10), so nothing can be injected into the HTML.
- **Route `POST /api/auth/send-email`.**
  - Body over 64 KiB → 413.
  - The signature is checked with `standardwebhooks` over the raw body, before any parsing: secret unset, missing
    headers, wrong signature, another secret's signature, a tampered body, or a timestamp more than 5 minutes away →
    401. The library compares in constant time and accepts any one of several space-separated signatures (rotation).
  - zod payload → 400.
  - Action types:
    - `magiclink` → 200, no send (A00-1).
    - `signup`, `recovery`, `invite` → one code email.
    - `email_change` → `token` to `user.email` and `token_new` to `user.new_email`. Any other shape → 400.
    - `password_changed_notification` → passed: the security notice (03-11a wave note).
    - Anything else → 200, dropped and logged.
  - 200 only after the provider accepts every message. `disabled` → 503 and a provider failure → 500, both in the
    hook error shape `{ error: { http_code, message } }`.
  - Log lines: `auth.email.{sent,dropped,refused,failed}` with action (or `unrecognised`), `module`
    `auth.email.<provider>`, count or reason, status, error code and request id. Never an address, a code, a token
    hash or provider text.
- **Env (R-15, same commit `0a08598`).**
  - `EMAIL_PROVIDER` (`mailpit|ses|disabled`): defaults to `disabled` outside staging/production. Required in
    staging (`ses` or `disabled`, R-16) and production (`ses` only). `mailpit` is refused in staging/production.
  - `EMAIL_FROM`: email shape; required for `ses` and `mailpit`.
  - `MAILPIT_API_URL`: loopback in every tier; required for `mailpit`.
  - `SES_ACCESS_KEY_ID` (`AKIA` + 16) and `SES_SECRET_ACCESS_KEY` (≥ 40): required for `ses` (R-31).
  - `SEND_EMAIL_HOOK_SECRET`: `v1,whsec_<base64>`, decoded key ≥ 24 bytes, required in production and with `ses`. A
    decoded `not-real` key is refused in staging/production.
  - The rest of the checklist, in the same commit: `ENV_DOCS` group "Email", `.env.example` regenerated by the
    script, accessor via `serverEnv()`, unit cases, the test-lane pins and the e2e value.
  - Test lane (`tests/setup/test-env.ts`): `EMAIL_PROVIDER` unset or `disabled|mailpit`. `SEND_EMAIL_HOOK_SECRET`
    unset or `LOCAL_SEND_EMAIL_HOOK_SECRET` (assembled at runtime, never echoed). `MAILPIT_API_URL` must be loopback.
    `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`, `AWS_SESSION_TOKEN`, `SES_ACCESS_KEY_ID` and
    `SES_SECRET_ACCESS_KEY` are forbidden.
  - e2e server: `EMAIL_PROVIDER=mailpit`, `MAILPIT_API_URL=http://127.0.0.1:54324`,
    `EMAIL_FROM=no-reply@auth.example.com`, the local hook secret.
  - `/api/ready` `providers.email` is `configured` only for `ses` (03-01 handoff).
- **Guard (P0-13).** New `RouteGuard` kind `webhook-signature`. Manifest entry
  `app/api/auth/send-email/route.ts#POST`. Engine leg `webhookSignatureRouteLegs`: secret unset (validly signed), no

- **Fixtures** `lint-fixtures/auth-hook/*.json`: seven synthetic payloads with the spike E3 key lists, the shapes

## GoTrue hook shapes (local spike, tool output)

`supabase/config.toml` was changed temporarily: the hook was enabled with the secret passed through `env()`, so no
secret was written to the file. It pointed at a scratch receiver that recorded shapes only. Then
`supabase stop` / `start` ran, synthetic users triggered each email, and the original config was restored (`git
checkout`) and the stack restarted. No test-run lock was held. GoTrue v2.197.0, recorded in
`evidence/03-11b/gotrue-hook-shapes.jsonl`:
- the signature verified on every call (headers `webhook-id`, `webhook-signature`, `webhook-timestamp`);
- action types seen: `recovery`, `invite`, `magiclink`, `password_changed_notification` (empty `token`),
  `reauthentication` and `email_change` (`token` and `token_new` both 6 digits, `user.new_email` set);
- a scratch `verifyOtp` confirmed the mapping: `token` belongs to the current address and `token_new` to the new one.
  Both were required to complete the change.
The CLI rejects a hook secret that is not `v1,whsec_<base64>` of at least 32 characters, and the env rule matches.

## Deviations and interpretations (for review D and the PO)

1. **Env names (Rule 1/3; affects PO action E4 wording, not E6/E8).** The plan names `AWS_REGION` in the schema,
   and E4 tells the PO to set `AWS_REGION`, `AWS_ACCESS_KEY_ID` and `AWS_SECRET_ACCESS_KEY` in Vercel. Vercel
   **reserves** all three (`evidence/03-11b/vercel-reserved-env-names.txt`).
   - The PO could not set them.
   - At runtime they hold the platform's own values, so the SDK default chain would sign with Vercel's credentials.
   - A schema rule on `AWS_REGION` would also break `next build` on Vercel, whose build region is not ap-south-1.
   - Shipped instead:
     - `SES_ACCESS_KEY_ID` / `SES_SECRET_ACCESS_KEY`, passed explicitly to the client (R-31 intent unchanged: the
       least-privilege IAM user's keys in Vercel);
     - the region is the constant `SES_REGION = "ap-south-1"` (PO-A3), with no env name;
     - the default credential chain is never used.
   - E6/E8 names are unchanged (`clinicos-staging-ses`, `auth.<domain>`, `SEND_EMAIL_HOOK_SECRET`, `EMAIL_PROVIDER`).
   - **The E4 text in `03-PLAN.md` and `.planning/PO-ACTIONS.md` (lines ~129-131) needs amending**; the runbook
     already uses the new names. PO confirms at E13.
2. **SES pin re-check (03-10 wave note).** The "same train as the S3 SDK" rationale is gone.
   - `3.1155.0` is kept: it is the E14 name, and it is now 22 days old.
   - Its caret dependencies would have pulled 1-day-old packages, so the new tree was resolved with
     `npm install --before=2026-11-06T00:00:00Z`. All 26 new entries are at least 7 days old.
   - A cutoff at the pin's own date was tried first. It resolved `@smithy/core` 3.36.2, which is **deprecated**: every
     version up to 3.38.0 has a logger-redaction bug (aws-sdk-js-v3#8393;
     `evidence/03-11b/smithy-core-deprecations.txt`). The lock has 3.39.0.
   - `standardwebhooks` declares a `prepare` script. Registry installs do not run it, and neither package has
     preinstall/install/postinstall.
   - New tool `scripts/ci/package-legitimacy.mjs` writes the record; 03-12c can append its part.
3. **`password_changed_notification`** is passed (03-11a note), confirmed as the real action type. **`reauthentication`**
   and every other type are dropped (default deny; the app does not use reauthentication: secure password change is
   off, A00-5 uses "require current password").

5. **Invite copy** is new: there is no `supabase/templates/invite.html`, and the app sends no invites through GoTrue

6. **Rule 2 additions:** 64 KiB body cap (413); action strings outside `[a-z_]{1,40}` are logged as `unrecognised`;
   codes must be digits; Mailpit refuses non-http(s) URLs.
7. **Mailpit needs explicit `MAILPIT_API_URL` and `EMAIL_FROM`** (no defaults), so a local config says what it does.
8. **No real-GoTrue-code round trip in the Mailpit spec.** Obtaining a code without an email needs

## Threat flags

| Flag | File | Description |
|---|---|---|
| threat_flag: replay | `app/api/auth/send-email/route.ts` | No `webhook-id` dedupe. A captured request (TLS makes that unlikely) could be replayed within the 5-minute tolerance and would re-send the same email to the same address. Dedupe needs storage: V2-04 outbox |
| threat_flag: dos | same | Public route. Each call costs one HMAC over at most 64 KiB, and the proxy session refresh (`getClaims`, no cookies). No app-level rate limit; Vercel limits only |
| threat_flag: config | `lib/env.ts` | `EMAIL_PROVIDER=disabled` in staging makes every auth email fail (503) by design (R-16). Production refuses it |
