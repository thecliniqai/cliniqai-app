## What shipped

`BOUNDARY_SYNTAX` (`no-restricted-syntax`) and `BOUNDARY_IMPORT_PATTERNS` / `BOUNDARY_IMPORT_PATHS`
(`@typescript-eslint/no-restricted-imports`, chosen over the core rule for per-path `allowTypeImports`). The default
object applies every group to every file. `BOUNDARY_SYNTAX_ZONES` and `BOUNDARY_IMPORT_ZONES` each emit one config
object per file set, built by `appSyntax(allow)` / `appImports(allow)`. Each of those objects gets the **whole** base

merge (pitfall 4). The spec proves this: AUTH-01 and P0-13 still fire in all 24 zone paths. The last object is the
tooling set (`tests/**`, `scripts/**`, the four root tool configs, per ADR-0005 D4), which keeps only the base gates.

## Deviations from the plan text (all tighter or recorded handoffs)

1. **`no-console` is a `no-restricted-syntax` group with the `P1-25:` prefix**, not the core rule. The plan wants
   prefixed, countable messages, and the selector also catches `globalThis.console` and aliasing.
2. **The console allow-list is exactly `lib/log/client.ts`**, not `lib/log/**`, per the 03-09c handoff. The server
   logger writes to stdout/stderr directly. A fixture proves `console` in `lib/log/index.ts` fails. The plan's pass
   case "console in `lib/log/x.ts`" is replaced by `lib/log/client.ts`.
3. **`process.env` and the secret-key names are allowed in explicit files** (`lib/env.ts`, `lib/env-server.ts`), not
   the glob `lib/env*.ts`. `lib/log/client.ts` is added for `process.env` (03-09a/03-01 handoffs).
   `lib/storage/supabase-provider.ts` is dropped from the identifier allow-list (03-02 handoff).
4. **jobs internals.** The plan says "nowhere outside `lib/jobs/**`". ADR-0005 D2 says the internal part is importable
   from `app/api/jobs/**` and other internals, so the ADR wins. The internal part is `lib/jobs/internal/**` (the V2-04
   04-PLAN layout). The enqueue surface (`lib/jobs/enqueue.ts`) importing an internal fails. The factory allowance
   stays `lib/jobs/**` as written in the plan; 04-02 narrows it to `lib/jobs/internal/**`.
5. **Wider P1-21 patterns:** `+05:30` literals (03-05 handoff), `toJSON()`, `.substr`, and any `.split("T")`. The
   literal ban follows the plan ("containing `T00:00:00`"), not 03-05's census regex C (`…Z` only). It is wider
   because a local-time parse is a UTC-midnight day window on the server (Vercel runs in UTC). This found one
   straggler, `components/calendar/doctor-timeline.tsx:63` (browser-side weekday; same result). It now uses
   `weekdayOfYmd`.
6. **Additions beyond the plan's list:** computed `import()` specifiers; dynamic import/require of `@supabase/*` client
   packages; non-canonical system-module spellings; `import x = require()`; re-exports and namespace imports (covered
   by the import rule); the `"use client"` server-logger ban (03-09c handoff: `lib/errors/client-message.ts` imports
   `lib/log`, and neither has `server-only`).
7. **Type-only imports of system modules are banned too.** Only `createClient`, `createServerClient` and
   `createBrowserClient` allow type imports, as the plan says. Today the only type importer of `SystemDb` is
   `features/sharing/system.ts`, which is allowed.
8. **The counters live in their own module** (`scripts/ci/p1-34-counters.mjs`, not in the plan's file list), so the
   spec exercises the exact function `phase-evidence.mjs` calls. `eslint.config.mjs` gains the named export
   `P134_CENSUS` (ESLint reads only the default export).
9. **Typecheck covers `lint-fixtures/`** (root `tsconfig.json` includes `**/*.ts`). Three fixtures import modules that
   do not exist at their real location (`lib/jobs` lands in V2-04), so they start with `// @ts-nocheck`. The README
   says so.
10. **typescript-eslint message shape:** `no-restricted-imports` messages read `'<spec>' import is restricted from
    being used by a pattern. P1-34: …`. The spec and the counters therefore match the id after whitespace, not as a
    prefix.
