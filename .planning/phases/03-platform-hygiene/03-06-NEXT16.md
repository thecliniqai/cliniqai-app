## What changed

- **`proxy.ts`** (was `middleware.ts`, `git mv`): export `proxy`; session refresh with `supabase.auth.getClaims()`
  (the only refresh point); `setAll(cookies, headers)` rebuilds the response, sets the cookies and copies the
  `Cache-Control`/`Expires`/`Pragma` headers 0.12 hands over; the proxy returns exactly that response. The API_V1
  gate, the `/api/health`/`/api/ready` early returns and the matcher are unchanged (the 57-case
  `tests/api/api-v1-switch.spec.ts`, which now imports `@/proxy`, passes; `unstable_doesMiddlewareMatch` is still the
  name Next 16.4.6 exports for the matcher test helper).
- **`lib/supabase/server.ts`**: 0.12 `setAll` types. It ignores the headers argument on purpose: Server Components and
  actions cannot set response headers, and the proxy sets them on every response that carries refreshed cookies.
  **`lib/supabase/client.ts` is unchanged**: `createBrowserClient(url, key)` has the same API in 0.12 and typechecks
  with the `Database` generic.
- **`eslint.config.mjs`**: native flat exports `eslint-config-next/core-web-vitals` + `eslint-config-next/typescript`;
  `FlatCompat` and the `@eslint/eslintrc` import are gone. Ignores and the AUTH-01 / P0-01 / P0-13 gates are unchanged;
  the three lint-gate specs pass. Same file set linted (447 before; 449 after = +2 new spec files; `middleware.ts` →
  `proxy.ts`).
- **CI / ownership**: both `.next/cache` keys in `ci.yml` hash `proxy.ts`; `CODEOWNERS` lists `/proxy.ts`.
- **F20**: both postcss-in-next waivers removed from `.github/audit-allowlist.json`: the audit gate reported them as
  STALE (no matching advisory with next 16.4.6, which bundles postcss 8.5.23) and fails on stale entries, so they were
  removed rather than renewed.
- **Build scan (`tests/e2e/support/build-scan.ts`)**: it already walks all of `.next/static/` and `.next/server/`, which
  covers the Turbopack layout (browser chunks in `static/chunks/`, server chunks in `server/chunks/` and
  `server/chunks/ssr/`, route entries in `server/app/`; no symlinks inside either tree). Added: the scan now fails if
  any of those three directories holds no JavaScript, so a future layout change cannot leave it clean over an empty
  tree. `.next/build/` (build-time PostCSS chunks) and `.next/node_modules/` (symlinks to `serverExternalPackages`)
  hold no app output. **Planted-marker proof:** a throwaway build with a hosted `*.supabase.co` literal in the login
  page (client) and in `/api/health` (server) was refused with 4 findings, in `.next/static/chunks/…js` and
  `.next/server/chunks/…js` (+ maps) (`after/e2e-build-planted-marker.txt`); the two files were restored from copies
  and the clean build re-run.
- `@react-pdf/renderer` builds under Turbopack as a `serverExternalPackages` entry; the PR lane's
  `consult-rx-finish` flow fetches a prescription PDF from the built app and gets `%PDF-`.

## Deviations from the plan

1. **Baseline SHA.** The baseline ran on `a36ef48` (= `e66edf9` + the docs-only `081dbec` + the guard-input fix below),
   not on `e66edf9` itself; the app code is identical.
2. **Flaky guard test root-caused and fixed (`a36ef48`, outside the series).** The first baseline failed
   `guard-actions` leg 3b `bookAppointment` with `conflict: true`. Cause: `futureIso` in
   `tests/security/guard/valid-inputs.ts` picked a random minute in a 600-minute window, the legs book the same doctor
   several times per run, and the scheduler flags any two visits within 15 minutes, so each pair collided about 5% of
   the time. It now hands out distinct one-hour slots. Not retried to green.
3. **Local stack partially restarted by an earlier session.** The same first baseline failed 5 AUTH-04a reset tests:
   Kong had been up 12 h while auth/db/storage were restarted 50 min earlier, and GoTrue's template fetch
   (`http://supabase_kong_clinicos:8088/email/recovery.html`) returned 404, so recovery emails went out with the
   default subject and later requests hit the email limit. `npx supabase stop` + `npx supabase start -x …` (data kept)
   fixed it; the two suites then passed and the whole baseline was re-run. Environment, not code.
4. **Codemod rename ignored `--dry`** (see the codemod table); reverted at once, and the affected baseline run was
   discarded.
5. **`next-async-request-api` codemod output rejected** as a false positive (diff kept).
6. **Three React Compiler lint rules set to `warn`** (+35 warnings, owner V2-06), as plan step 5 allows.
7. **F20 waivers removed, not renewed** (the gate marks them stale).
8. **`lib/supabase/client.ts` not edited**: no API change in 0.12 needed one.
9. **Local CI-env build** ran under `env -i` with only the CI build variables plus `__NEXT_PROCESSED_ENV=true` and
   `NEXT_TELEMETRY_DISABLED=1`, standing in for CI's checkout with no `.env`. Next prints `- Environments: .env` on
   both 15.5.28 and 16.4.6 (it lists the file); the K-2 flag stops it assigning anything (pinned by
   `next-env-flag.spec.ts`). One earlier exploratory `npm run build` under `env -i` ran without
   `NEXT_TELEMETRY_DISABLED`, so Next's anonymous build telemetry may have been sent once (no app data, no env values).
10. **Approved-doc erratum not applied** (R-24): ADR-0005 D4's owner list still names `middleware.ts`; the change to
    `proxy.ts` is proposed for 03-SUMMARY and applied only after PO confirmation.
