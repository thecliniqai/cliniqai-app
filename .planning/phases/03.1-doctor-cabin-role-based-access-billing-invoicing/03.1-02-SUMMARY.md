## 1. Executive Overview

Plan `03.1-02` integrated 1-tap consultation workflows across all primary clinic operational touchpoints: **Live Queue**, **Main Dashboard**, and **Doctor Calendar Timeline**.

Before this plan, clinic staff and doctors had to guess how to enter the consultation workspace because queue buttons only updated database status in-place without triggering navigation. This plan wires up seamless, immediate routing:

1. **Live Queue 1-Tap Launch (`components/queue/status-actions.tsx`, `queue-card.tsx`):**
   - For `waiting` visits: Primary button with Stethoscope icon: `Start Consultation`. Transitions visit to `in_consultation` and immediately routes the browser to `/consultation/[id]`.
   - For `in_consultation` visits: Primary button: `Resume Consultation` with direct routing to `/consultation/[id]`, plus secondary `Done` action to mark completed.
   - For `completed` visits: `Completed` badge + `Review` link to inspect notes and prescriptions.

2. **Dashboard Overview Table (`app/(dashboard)/page.tsx`):**
   - Replaced generic "Manage" buttons with intelligent context-aware actions:
     - `waiting` -> `Consult` button (primary blue) linking directly to `/consultation/[id]`.
     - `in_consultation` -> `Resume` button (primary blue) linking to active session.
     - `completed` -> `Review` link.

3. **Calendar Doctor Timeline (`components/calendar/doctor-timeline.tsx`):**
   - Appointment cards in timeline columns feature a direct Stethoscope icon button linking directly to `/consultation/[id]`, isolated with `stopPropagation()` from the slot booking handler.

4. **Automated Verification:**
   - Unit test `tests/queue/status-actions.spec.ts` passing (5/5 tests).
   - Integration test `tests/integration/cabin-consultation-launch.spec.ts` passing against live Supabase: creates visit -> checks in -> transitions to `in_consultation` -> saves consultation SOAP draft -> verifies cross-tenant RLS isolation.
   - Zero TypeScript errors (`npm run typecheck`).
