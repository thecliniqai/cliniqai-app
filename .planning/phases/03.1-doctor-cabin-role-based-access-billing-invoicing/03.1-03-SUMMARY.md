## 1. Executive Overview

Plan `03.1-03` built the complete data layer, transactional server actions, and dual clinical/receptionist UI workflows for **per-visit billing, consultation fee checkout, and payment recording** (`REQ-billing-invoicing`, `REQ-multi-tenancy`).

Key capabilities delivered:

1. **Database Schema & RLS Isolation (`supabase/migrations/000009_billing_invoicing_payments.sql`):**
   - Tables `invoices`, `invoice_items`, and `payments` with strict foreign keys to `tenants`, `visits`, and `patients`.
   - Atomic invoice sequence generator `generate_invoice_number(tenant_id)` generating format `INV-YYYY-XXXX`.
   - Tenant settings columns on `tenants`: `owner_is_practicing_doctor`, `default_consultation_fee`, `default_followup_fee`, `accepted_payment_methods`.
   - Postgres Row Level Security (RLS) policies on all tables ensuring zero cross-tenant access.

2. **Server Actions & Zod Schemas (`features/billing/schema.ts`, `features/billing/actions.ts`):**
   - `createVisitInvoice`: Itemizes consultation fees, procedure charges, discounts, and computes totals with exact 2-decimal floating-point safety (`Math.round((val + Number.EPSILON) * 100) / 100`).
   - `recordPayment`: Records payments (`cash`, `upi`, `card`), calculates total paid vs remaining balance, transitions status to `paid` once settled, and writes audit event `invoice.payment_recorded`.
   - `getVisitBillingDetails`: Returns invoices, line items, and payment transactions for a given `visit_id`.

3. **Solo Doctor Integrated Sign & Bill Modal (`components/consultation/sign-and-bill-modal.tsx`):**
   - Enables solo practitioners to seal clinical consultation notes, generate invoice, and record payment in one step.
   - Pre-fills clinic default consultation fee; supports 1-tap method selection (`Cash`, `UPI`, `Card`, `Unpaid / Pay Later`).
   - Emits branded receipt and completes visit lifecycle.

4. **Reception Checkout Drawer (`components/queue/checkout-drawer.tsx`):**
   - Front-desk workflow integrated in Live Queue (`/queue`) for clinics with separate reception staff.
   - Allows receptionists to select any completed or pending visit, review charges, add procedure line items, record payment, and issue receipt.

5. **Automated Verification:**
   - Unit tests in `tests/billing/schemas.spec.ts` (4/4 passing) validating Zod schemas for amounts, methods, items, and boundary conditions.
   - Integration tests in `tests/integration/per-visit-billing.spec.ts` (5/5 passing against live Supabase) validating invoice generation, partial payments, status transitions (`issued` -> `paid`), and tenant RLS isolation.
   - TypeScript typecheck passing with 0 errors (`npm run typecheck`).
