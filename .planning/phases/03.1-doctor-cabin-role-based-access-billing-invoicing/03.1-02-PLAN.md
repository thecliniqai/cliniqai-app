<objective>
Wire up direct 1-tap consultation entry points across the Live Queue, Calendar timeline, and Dashboard:
1. Update `components/queue/status-actions.tsx` and `queue-card.tsx` so that clicking "Start Consultation" updates visit status to `in_consultation` and immediately navigates into `/consultation/[id]`, and shows "Resume Consultation" for in-progress visits.
2. Update the Dashboard table (`app/(dashboard)/page.tsx`) with direct `Consult` action buttons for active patients.
3. Update `components/calendar/doctor-timeline.tsx` so clicking an active patient visit opens their consultation.
4. Add unit and integration tests proving seamless transition from queue/dashboard into `/consultation/[id]`.
</objective>

<threat_model>
| Threat ID | Category | Component | Description | Severity | Mitigation |
|-----------|----------|-----------|-------------|----------|------------|
| T-03.1-03 | Broken Object Level Authorization (BOLA) | Consultation Launch | Malicious user manipulating visit IDs in queue actions to access unauthorized visits. | high | `features/queue/actions.ts` and `/consultation/[id]` validate that the visit belongs to the user's active tenant and that the user holds authorized role membership. |
| T-03.1-04 | Race Conditions | Concurrent Status Transitions | Two staff members clicking "Start Consultation" concurrently causing duplicate token or invalid state progression. | medium | Use database-level row locking (`SELECT FOR UPDATE`) or atomic status transition conditions (`WHERE status = 'waiting'`). |
</threat_model>
