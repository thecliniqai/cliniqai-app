Build the data layer and architectural tracer for Phase 2: migration `000006_appointments_queue_waitlist.sql` extending `patients` with `age`, creating `visits` (unified scheduled/walk-in model), `queue_tokens` (daily sequential token layer), and `waitlist_entries` with comprehensive Row Level Security policies and atomic token assignment RPC.

<task type="tracer">
  <name>Task 1: Migration 000006 and TypeScript Database Types</name>
  <files>supabase/migrations/000006_appointments_queue_waitlist.sql, lib/db/types.ts</files>
  <action>
    Create migration `000006_appointments_queue_waitlist.sql`:
    1. Alter `patients`: add `age INTEGER`, `allergies TEXT[] DEFAULT '{}'`, `chronic_conditions TEXT[] DEFAULT '{}'`, `emergency_contact JSONB`.
    2. Create `visits`: `id UUID PK`, `tenant_id UUID FK`, `patient_id UUID FK`, `doctor_id UUID FK`, `origin_type TEXT ('scheduled', 'walk_in')`, `status TEXT ('booked', 'confirmed', 'waiting', 'in_consultation', 'completed', 'cancelled', 'no_show')`, `scheduled_at TIMESTAMPTZ`, `estimated_duration_minutes INTEGER DEFAULT 15`, `reason_for_visit TEXT`, `is_overbooked BOOLEAN DEFAULT false`, `created_by UUID FK`, `created_at`, `updated_at`.
    3. Create `queue_tokens`: `id UUID PK`, `tenant_id UUID FK`, `visit_id UUID UNIQUE FK`, `date DATE DEFAULT CURRENT_DATE`, `token_number INTEGER`, `priority TEXT ('normal', 'urgent', 'vip')`, `called_at TIMESTAMPTZ`, `completed_at TIMESTAMPTZ`, `created_at`. Unique constraint `(tenant_id, date, token_number)`.
    4. Create `waitlist_entries`: `id UUID PK`, `tenant_id UUID FK`, `patient_id UUID FK`, `doctor_id UUID FK (nullable)`, `target_date DATE`, `time_window TEXT`, `status TEXT ('waiting', 'promoted', 'expired', 'cancelled')`, `promoted_visit_id UUID FK`, `priority INTEGER DEFAULT 0`, `notes TEXT`, `created_by UUID FK`, `created_at`.
    5. RPC `generate_daily_queue_token(p_tenant_id UUID, p_date DATE)`: returns next sequential integer for the tenant and date.
    6. Enable RLS and create tenant-isolation policies for all three new tables.
    7. Update `lib/db/types.ts` with complete typed interfaces.
  </action>
  <verify>
    <automated>npm run typecheck</automated>
  </verify>
</task>

<task type="auto">
  <name>Task 2: Visit & Queue Server Actions with Audit Logging</name>
  <files>features/visits/actions.ts, features/queue/actions.ts</files>
  <action>
    Implement Server Actions:
    1. `features/visits/actions.ts`:
       - `createVisit`: checks membership, derives tenant_id, inserts into `visits`, logs audit event `visit.create`.
       - `getVisitsForDate`: fetches visits for given date filtered by tenant_id and optional doctor_id.
       - `updateVisitStatus`: updates visit status (e.g. booked -> confirmed -> cancelled), logs audit event.
    2. `features/queue/actions.ts`:
       - `checkInVisit`: calls `generate_daily_queue_token`, inserts row into `queue_tokens`, flips visit status to `waiting`, logs audit event `queue.check_in`.
       - `transitionQueueState`: transitions `waiting` -> `in_consultation` (sets `called_at`) or `in_consultation` -> `completed` (sets `completed_at`).
  </action>
